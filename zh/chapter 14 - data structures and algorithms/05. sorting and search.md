# 排序、搜索与算法设计

*排序与搜索是最基础的算法操作。本节涵盖排序算法、二分搜索模式、分治、贪心算法、动态规划和回溯。*

- 每种数据结构都支撑算法，每个算法都依赖数据结构。本节讨论**设计范式（design paradigms）**，即解决问题的高层策略。一旦识别出适用范式，实现会自然随之而来。

## 排序算法

- 排序是计算机科学中研究最充分的问题。理解这些算法可以建立递归、分治与复杂度分析的直觉。

!!! note "大白话"
    排序本身很常见，更重要的是它把“拆分、合并、选择、复杂度”这些算法核心思想集中展示出来。

| 算法 | 最好 | 平均 | 最坏 | 空间 | 稳定？ |
|-----------|------|---------|-------|-------|---------|
| 冒泡排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 是 |
| 插入排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 是 |
| 归并排序 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(n)$ | 是 |
| 快速排序 | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | $O(\log n)$ | 否 |
| 堆排序 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | 否 |
| 计数排序 | $O(n + k)$ | $O(n + k)$ | $O(n + k)$ | $O(k)$ | 是 |
| 基数排序 | $O(d(n + k))$ | $O(d(n + k))$ | $O(d(n + k))$ | $O(n + k)$ | 是 |

!!! note "大白话"
    不同排序是在时间、内存、稳定性和最坏情况之间取舍，不存在所有场景都最好的一个。

- **稳定（Stable）**表示相等元素保留其相对顺序。按多个键排序时这很重要。

!!! note "大白话"
    稳定排序不会打乱原本相等元素的先后顺序，所以可以先按次要键排，再按主要键排。

- 基于比较的排序的**下界（lower bound）**是 $\Omega(n \log n)$。证明使用决策树，第 13 章：任何比较排序都必须区分全部 $n!$ 种排列，因此至少需要 $\log_2(n!)  = \Omega(n \log n)$ 次比较。计数排序与基数排序无需比较元素，故能突破该下界。

!!! note "大白话"
    只靠两两比较，任何排序都躲不开 $n \log n$ 级别；计数排序利用整数范围等额外信息，才有机会更快。

### 归并排序

- 将数组一分为二，递归排序两半，再合并已排序部分。始终为 $O(n \log n)$，额外空间为 $O(n)$。

!!! note "大白话"
    归并排序先把问题不断对半拆小，再把两个有序小段像拉拉链一样合并，时间稳定但需要临时空间。

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])

    return merge(left, right)

def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:  # <= for stability
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result
```

- **陷阱**：合并时使用 `<` 而非 `<=` 会破坏稳定性，相等元素中右半部分的元素会排到左半部分元素之前。

!!! note "大白话"
    相等时优先取左半边，才能保持它们原本的相对顺序。

### 快速排序

- 选择一个**枢轴（pivot）**，将元素划分为“小于枢轴”与“大于枢轴”，递归排序每个分区。平均为 $O(n \log n)$，最坏为 $O(n^2)$，枢轴始终是最小或最大元素时。

!!! note "大白话"
    快排每次选一个基准把数组分两边；分得均匀就快，老是分成一边空一边很长就会退化。

```python
def quicksort(arr, lo=0, hi=None):
    if hi is None:
        hi = len(arr) - 1
    if lo >= hi:
        return

    pivot_idx = partition(arr, lo, hi)
    quicksort(arr, lo, pivot_idx - 1)
    quicksort(arr, pivot_idx + 1, hi)

def partition(arr, lo, hi):
    pivot = arr[hi]  # Lomuto: pivot is last element
    i = lo
    for j in range(lo, hi):
        if arr[j] < pivot:
            arr[i], arr[j] = arr[j], arr[i]
            i += 1
    arr[i], arr[hi] = arr[hi], arr[i]
    return i
```

- **枢轴策略（Pivot strategies）**：最后元素，简单、对已排序输入差；随机，期望 $O(n \log n)$；三数取中，实践选择。面试中总是偏好随机枢轴，以避免最坏情况讨论。

!!! note "大白话"
    枢轴选得好坏决定分区是否均衡；随机或三数取中能减少连续选到极端值的风险。

- **陷阱**：对已排序数组使用首/尾枢轴时，快速排序最坏情况为 $O(n^2)$。实践中使用随机枢轴或三数取中可消除此问题。

!!! note "大白话"
    已排序数组配首尾枢轴最容易每次只剥掉一个元素，快排就不再“快”。

### 计数排序

- 值是已知范围 $[0, k)$ 内的整数时，统计出现次数并重建：时间 $O(n + k)$。它不基于比较，因此可以优于 $O(n \log n)$。

!!! note "大白话"
    计数排序不比较谁大谁小，而是直接数每个值出现几次，再按值重建数组。

```python
def counting_sort(arr, k):
    count = [0] * k
    for x in arr:
        count[x] += 1
    result = []
    for val in range(k):
        result.extend([val] * count[val])
    return result
```

- **何时使用**：范围 $k$ 不比 $n$ 大很多。若 $k = O(n)$，则为 $O(n)$；若 $k \gg n$，例如在 $[0, 10^9]$ 中排序 10 个数，计数排序浪费内存。

!!! note "大白话"
    数值范围小才适合开计数数组；范围巨大而数据很少时，计数数组会比原数据还浪费。

## 模式：二分搜索

- 二分搜索通过反复将搜索空间减半，在 $O(\log n)$ 内从有序数组中找目标。但它远不止“在有序数组找数字”。通用模式是：**在单调条件上搜索（search on a monotonic condition）**。

!!! note "大白话"
    二分的本质不是找某个数字，而是找到一个条件从假变真或从真变假的分界点。

- **模板**，可避免 off-by-one 错误：

```python
def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1

    while lo <= hi:
        mid = lo + (hi - lo) // 2  # avoids overflow in other languages
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1

    return -1  # not found
```

!!! note "大白话"
    每轮比较中点后，明确丢掉不可能的一半；循环条件和边界更新必须配套使用。

- **下界（Lower bound）**，第一个 $\geq$ 目标的元素：

```python
def lower_bound(arr, target):
    lo, hi = 0, len(arr)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

!!! note "大白话"
    下界不是找“等于目标”，而是找第一个不小于目标的位置，常用于插入位置和范围查询。

- **陷阱**：`lo <= hi` 与 `lo < hi` 的差异，以及 `hi = mid` 与 `hi = mid - 1` 的差异，决定找到精确匹配还是边界。用两元素数组画出来验证。

!!! note "大白话"
    二分最怕边界写混。先定义区间端点是否包含，再让循环条件和更新规则完全一致。

### 中等：搜索旋转排序数组

- **问题**：一个排序数组在某枢轴处旋转，找目标。

!!! note "大白话"
    数组只是从中间折开后接起来，虽然整体不完全有序，但每次仍至少有一半保持正常排序。

- **模式**：每一步总有一半保持有序。先确定哪半有序，再检查目标是否落在该半。

!!! note "大白话"
    判断有序的半边后，如果目标值落在其数值范围内就去那边，否则去另一边，仍能每次砍掉一半。

```python
def search_rotated(nums, target):
    lo, hi = 0, len(nums) - 1

    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid

        # left half is sorted
        if nums[lo] <= nums[mid]:
            if nums[lo] <= target < nums[mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        # right half is sorted
        else:
            if nums[mid] < target <= nums[hi]:
                lo = mid + 1
            else:
                hi = mid - 1

    return -1
```

- **陷阱**：`nums[lo] <= nums[mid]` 中的 `<=`，而非 `<`，至关重要。`lo == mid`，剩两个元素，时，必须正确识别有序半边。

!!! note "大白话"
    剩很少元素时等号决定哪一半被视为有序，少一个等号就可能把边界情况分错。

### 困难：两个有序数组的中位数

- **问题**：在 $O(\log(m + n))$ 内找出两个有序数组的中位数。

!!! note "大白话"
    不能简单合并两个数组，因为那是线性；要直接找到把两个数组切成左右两半的正确位置。

- **模式**：在较短数组的分割点上二分搜索。该分割将两个数组划分为左侧全部元素均小于右侧全部元素。

!!! note "大白话"
    搜索对象不是某个数，而是一个切口；切口两边总元素数正确且左边都不大于右边时，就找到了中位数。

```python
def find_median(nums1, nums2):
    if len(nums1) > len(nums2):
        nums1, nums2 = nums2, nums1  # ensure nums1 is shorter

    m, n = len(nums1), len(nums2)
    lo, hi = 0, m
    half = (m + n + 1) // 2

    while lo <= hi:
        i = (lo + hi) // 2          # partition point in nums1
        j = half - i                 # partition point in nums2

        left1 = nums1[i - 1] if i > 0 else float('-inf')
        right1 = nums1[i] if i < m else float('inf')
        left2 = nums2[j - 1] if j > 0 else float('-inf')
        right2 = nums2[j] if j < n else float('inf')

        if left1 <= right2 and left2 <= right1:
            # correct partition
            if (m + n) % 2 == 1:
                return max(left1, left2)
            return (max(left1, left2) + min(right1, right2)) / 2
        elif left1 > right2:
            hi = i - 1
        else:
            lo = i + 1
```

- 这是最难的二分问题之一。关键洞见是你搜索的不是数值，而是满足条件的**分割点（partition point）**。

!!! note "大白话"
    一旦把“找中位数”改看成“找合法分割点”，二分的单调结构就出现了。

### 元模式：对答案二分

- 很多表面不像二分的问题，都能通过对答案二分求解。若答案是数，且可编写单调函数 `is_feasible(x)`，对所有 $x \geq$ 最优值为 True，或对所有 $x \geq$ 最优值为 False，便可对 $x$ 二分。

!!! note "大白话"
    如果某个候选答案一旦可行，所有更大答案也可行，或反过来，就可以直接对答案范围二分。

- **例子**：“在 $d$ 天内运送全部包裹，船的最小容量是多少？”对容量二分；每个候选容量上，贪心检查全部包裹能否在 $d$ 天内运完。

!!! note "大白话"
    先猜容量，再线性模拟是否够用；容量越大越容易完成，所以可行性是单调的。

```python
def ship_within_days(weights, days):
    lo, hi = max(weights), sum(weights)

    while lo < hi:
        mid = (lo + hi) // 2
        # can we ship with capacity mid in <= days?
        current_load, num_days = 0, 1
        for w in weights:
            if current_load + w > mid:
                num_days += 1
                current_load = 0
            current_load += w

        if num_days <= days:
            hi = mid
        else:
            lo = mid + 1

    return lo
```

## 模式：贪心算法

- **贪心（greedy）**算法每一步做局部最优选择，希望由此得到全局最优。问题具有**贪心选择性质（greedy choice property）**，局部最优导向全局最优，和**最优子结构（optimal substructure）**，最优解包含子问题最优解，时贪心有效。

!!! note "大白话"
    贪心每一步都选眼前最好的，但只有能证明这种选择不会堵死全局最优时才能用，不能凭感觉。

### 中等：跳跃游戏

- **问题**：给定数组，其中 `nums[i]` 是位置 $i$ 的最大跳跃长度，判断能否到达最后索引。

!!! note "大白话"
    不必枚举每次跳多远，只要持续记录目前最远能到哪里。

```python
def can_jump(nums):
    max_reach = 0
    for i, jump in enumerate(nums):
        if i > max_reach:
            return False  # cannot reach this position
        max_reach = max(max_reach, i + jump)
    return True
```

- **为什么贪心有效**：只需知道最远可达位置。当前点超出最远可达位置就被困住；否则更新最远可达位置。

!!! note "大白话"
    所有到达同一位置的路线里，只有最远覆盖范围有价值；更近的范围永远不会更好。

### 中等：合并区间

- **问题**：合并重叠区间。

!!! note "大白话"
    先按开始时间排好，之后每个区间只需和当前合并结果的最后一个比较。

```python
def merge_intervals(intervals):
    intervals.sort(key=lambda x: x[0])
    merged = [intervals[0]]

    for start, end in intervals[1:]:
        if start <= merged[-1][1]:
            merged[-1][1] = max(merged[-1][1], end)
        else:
            merged.append([start, end])

    return merged
```

- **模式**：按开始时间排序，再贪心合并。当前区间和最后已合并区间重叠时延伸它，否则开始新合并区间。

!!! note "大白话"
    排序后，未来区间不会比当前开始得更早；因此只需维护最后一段已合并区间即可。

- **陷阱**：不能用 `merged[-1][1] = end`，而要用 `merged[-1][1] = max(merged[-1][1], end)`。一个区间可能完全包含于另一个区间，如 `[1, 10]` 和 `[2, 5]`。

!!! note "大白话"
    新区间即使重叠，也未必把右边界推得更远；直接覆盖会把原本更长的区间缩短。

## 模式：动态规划

- **动态规划（Dynamic programming, DP）**通过将问题拆成重叠子问题、每个子问题只求解一次并保存结果来解决问题。问题具备**最优子结构（optimal substructure）**和**重叠子问题（overlapping subproblems）**时适用。

!!! note "大白话"
    DP 再次出现的原因很简单：同一个小问题会重复出现，缓存一次就不用反复重算。

- **两种方法**：
    - **自顶向下（Top-down）**，记忆化：写自然递归解，再在字典中缓存结果。
    - **自底向上（Bottom-up）**，制表：从最小子问题向上构建表。

!!! note "大白话"
    自顶向下从目标递归并缓存，自底向上先填最小情况再逐步推大；结果相同，写法和性能取舍不同。

- **如何识别 DP**：题目要求最优值，最小/最大、计数或存在性，且当前决策依赖先前决策。画递归树后看到重复子问题，就是 DP。

!!! note "大白话"
    看到“最优、多少种、能不能”和重复子问题时，先尝试定义 `dp` 状态，而不是暴力枚举全部路径。

### 简单：爬楼梯

- **问题**：有 $n$ 级台阶，每次可爬 1 或 2 级，有多少种不同方法？

!!! note "大白话"
    到第 $n$ 级的最后一步只有两种可能：从第 $n-1$ 级走一步，或从第 $n-2$ 级走两步。

- 这就是斐波那契：$f(n) = f(n-1) + f(n-2)$。

!!! note "大白话"
    这题和斐波那契同一个递推结构，每一级的方法数等于前两级方法数之和。

```python
def climb_stairs(n):
    if n <= 2:
        return n
    a, b = 1, 2
    for _ in range(3, n + 1):
        a, b = b, a + b
    return b
```

- $O(n)$ 时间、$O(1)$ 空间。无需完整记忆化表，因为每个状态仅依赖前两个状态。

!!! note "大白话"
    只保留最近两个状态就够了，不必把所有楼层的方法数都存下来。

### 中等：零钱兑换

- **问题**：给定硬币面额和目标金额，找出所需硬币最少数量。

!!! note "大白话"
    对每个金额，尝试最后放哪枚硬币，取所有合法方案里硬币数量最少的那个。

- **状态**：`dp[amount]` = 凑出 `amount` 所需最少硬币数。
- **转移**：对每个硬币，`dp[amount] = min(dp[amount - coin] + 1)`。
- **基例**：`dp[0] = 0`。

!!! note "大白话"
    状态定义的是“凑到这个金额最少要几枚”；零元不需要硬币，其他金额从更小金额加一枚转来。

```python
def coin_change(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0

    for a in range(1, amount + 1):
        for coin in coins:
            if coin <= a and dp[a - coin] + 1 < dp[a]:
                dp[a] = dp[a - coin] + 1

    return dp[amount] if dp[amount] != float('inf') else -1
```

- **陷阱**：应以 `float('inf')` 初始化，而不是 0 或 -1。只有不可达状态为无穷时，最小值比较才正确。

!!! note "大白话"
    初始要表示“目前还不知道、相当于无限大”，用 0 会错误地让不可达方案看起来最优。

### 中等：最长公共子序列

- **问题**：给定两个字符串，找出最长公共子序列长度。

!!! note "大白话"
    子序列可以跳过字符但不能改变顺序，要找两段文字中都能按原顺序保留的最长部分。

- **状态**：`dp[i][j]` = `text1[:i]` 与 `text2[:j]` 的 LCS。
- **转移**：若 `text1[i-1] == text2[j-1]`，则 `dp[i][j] = dp[i-1][j-1] + 1`；否则，`dp[i][j] = max(dp[i-1][j], dp[i][j-1])`。

!!! note "大白话"
    两个末尾字符相同就一起计入；不同就放弃其中一边的末尾，取两种可能里较长的结果。

```python
def longest_common_subsequence(text1, text2):
    m, n = len(text1), len(text2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i - 1] == text2[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    return dp[m][n]
```

### 困难：0/1 背包

- **问题**：给定具有重量和值的物品以及容量 $W$，在不超过 $W$ 时最大化总价值。

!!! note "大白话"
    每件物品只有“拿或不拿”两种选择，目标是在容量限制内装出价值最高的一包。

- **状态**：`dp[i][w]` = 使用前 $i$ 件物品、容量为 $w$ 时的最大价值。
- **转移**：`dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i])`，跳过或选取物品 $i$。

!!! note "大白话"
    当前物品要么跳过，沿用旧答案；要么放进去，腾出重量后加上它的价值，二者取大。

```python
def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]

    for i in range(1, n + 1):
        for w in range(capacity + 1):
            dp[i][w] = dp[i - 1][w]  # skip item i
            if weights[i - 1] <= w:
                dp[i][w] = max(dp[i][w],
                               dp[i - 1][w - weights[i - 1]] + values[i - 1])

    return dp[n][capacity]
```

- **空间优化**：每行仅依赖前一行时，可使用一维数组，并从右向左迭代 $w$：

```python
def knapsack_optimised(weights, values, capacity):
    dp = [0] * (capacity + 1)
    for i in range(len(weights)):
        for w in range(capacity, weights[i] - 1, -1):  # right to left!
            dp[w] = max(dp[w], dp[w - weights[i]] + values[i])
    return dp[capacity]
```

!!! note "大白话"
    一维表从右向左更新，是为了让当前物品不会在同一轮被重复使用。

- **陷阱**：在一维版本中从左向右迭代会允许物品 $i$ 被使用多次，变成完全背包。从右向左才能确保每件物品至多使用一次。

!!! note "大白话"
    更新方向就是 0/1 背包和完全背包的分水岭：从左会读到本轮刚写的值，从右才只读上一轮状态。

## 模式：回溯

- **回溯（Backtracking）**是带剪枝的穷举搜索。逐步构建解，一旦部分解不可能导向有效完整解，就放弃并回溯。

!!! note "大白话"
    回溯会系统试所有选择，但在确定走不通时提前刹车，不把无效路线走到底。

- **模板**：

```python
def backtrack(candidates, path, result):
    if is_solution(path):
        result.append(path[:])  # copy!
        return

    for candidate in get_candidates(path):
        if is_valid(candidate, path):
            path.append(candidate)     # choose
            backtrack(candidates, path, result)  # explore
            path.pop()                 # unchoose (backtrack)
```

!!! note "大白话"
    模板的关键仍是选择、递归探索、撤销；保存答案时要复制路径，避免后续修改把已保存结果一起改掉。

### 中等：子集

```python
def subsets(nums):
    result = []
    def backtrack(start, path):
        result.append(path[:])
        for i in range(start, len(nums)):
            path.append(nums[i])
            backtrack(i + 1, path)
            path.pop()
    backtrack(0, [])
    return result
```

### 中等：组合总和

- **问题**：找出全部和为目标值的唯一组合，元素可重复使用。

!!! note "大白话"
    每个候选数可以重复拿，直到凑够目标；排序后遇到过大的候选就能剪枝。

```python
def combination_sum(candidates, target):
    result = []
    def backtrack(start, path, remaining):
        if remaining == 0:
            result.append(path[:])
            return
        for i in range(start, len(candidates)):
            if candidates[i] > remaining:
                break  # prune: sorted, so all further candidates are too large
            path.append(candidates[i])
            backtrack(i, path, remaining - candidates[i])  # i, not i+1: reuse allowed
            path.pop()

    candidates.sort()  # sort for pruning
    backtrack(0, [], target)
    return result
```

- **陷阱**：`backtrack(i, ...)` 允许复用同一元素；`backtrack(i + 1, ...)` 则移至下一个元素，不可复用。搞错它是最常见的回溯 bug。

!!! note "大白话"
    递归下一层从 `i` 还是 `i + 1` 开始，直接决定当前元素能不能再次使用。

### 困难：N 皇后

- **问题**：放置 $n$ 个皇后在 $n \times n$ 棋盘上，使任意两个都不能互相攻击。

!!! note "大白话"
    每行放一个皇后，同时不能和之前皇后占同列或同一条对角线。

```python
def solve_n_queens(n):
    result = []
    cols = set()
    pos_diag = set()  # (row + col) is constant on / diagonals
    neg_diag = set()  # (row - col) is constant on \ diagonals

    board = [['.' ] * n for _ in range(n)]

    def backtrack(row):
        if row == n:
            result.append([''.join(r) for r in board])
            return

        for col in range(n):
            if col in cols or (row + col) in pos_diag or (row - col) in neg_diag:
                continue

            cols.add(col)
            pos_diag.add(row + col)
            neg_diag.add(row - col)
            board[row][col] = 'Q'

            backtrack(row + 1)

            cols.remove(col)
            pos_diag.remove(row + col)
            neg_diag.remove(row - col)
            board[row][col] = '.'

    backtrack(0)
    return result
```

- **关键洞见**：对角线编码。`/` 对角线上的 `row + col` 恒定；`\` 对角线上的 `row - col` 恒定。使用集合跟踪列和对角线，使有效性检查为 $O(1)$。

!!! note "大白话"
    用行列坐标的和与差给两类对角线编号，就能用集合瞬间判断冲突，不必逐个皇后检查。

## 常见陷阱汇总

| 陷阱 | 示例 | 修复 |
|---------|---------|-----|
| 二分中的 `lo <= hi` 与 `lo < hi` | 边界 off-by-one | 根据 `hi` 是包含还是排除来选择 |
| 一维背包从左到右 | 物品被使用多次 | 0/1 背包从右向左迭代 |
| 回溯中未复制路径 | `result.append(path)`，全部条目指同一列表 | `result.append(path[:])` 或 `path.copy()` |
| `backtrack(i)` 与 `backtrack(i+1)` | 元素复用与不可复用 | 与题目要求一致 |
| 有序回溯缺少 `break` | 探索过大的候选项 | 排序后，候选超出剩余值即 `break` |
| DP 初始化 | `dp[0]` 错误 → 后续全错 | 谨慎定义基例 |
| 无证明地使用贪心 | 贪心并不总有效 | 验证贪心选择性质 |
| 多键排序使用不稳定排序 | 相等元素的相对顺序丢失 | 使用稳定排序，归并、Python `sorted` |

!!! note "大白话"
    排序、二分、DP 和回溯的错误多在边界与状态定义；先写清区间、初值、是否复用，再实现会稳很多。
