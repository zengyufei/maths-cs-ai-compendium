    基础：大 O、递归、回溯与动态规划¶

    在进入数据结构和算法前，需要掌握四个基础概念：用大 O 表示法衡量效率、用递归把问题拆成子问题、用回溯在剪枝下穷举搜索，以及用动态规划避免重复计算。本节从第一原则讲解它们。

    • 本章余下各节都默认你熟悉这四个思想。若跳过本节，后文的 \(O(n \log n)\) 标注、递归树遍历、回溯模板和 DP 状态转移会像魔法，而非工程方法。

    大白话

    这一节是在学后面所有算法题都会反复用到的四把工具：估算成本、拆小问题、试错回退、缓存重复结果。

    为什么要学模式，而不是死记¶

    • LeetCode、NeetCode 和 HackerRank 上有数千道编码题。没人能全部记住，试图记住也是必败策略。面试官不会从固定题单中挑题，他们会修改、组合和伪装题目。死记 “Two Sum” 的解法，无法帮助你应对从未见过的变体。

    大白话

    题目数量太多，靠背答案一定会失效；真正要记的是解决问题的套路。

    • 好消息是，核心模式只有约 15-20 种，双指针、滑动窗口、BFS/DFS、DP、回溯等。每个问题无论表面多新颖，都会归结为一种或多种模式。面试并非考察你是否见过这道确切题目，而是考察你能否剥离语境（peel away the context），即故事、特定数据类型和边界情形，并识别底层模式。

    大白话

    题目换了故事，底层结构往往没变；先把故事剥掉，再看它属于哪种算法模式。

    • 考虑这三个问题：

      • “找出数组中和为目标值的两个数。”
      • “找出结合能之和达到阈值的两个分子。”
      • “给定账户余额列表，找出合计金额等于债务的两个账户。”

    • 它们看似不同，其实是同一问题：两数之和（Two Sum）。语境，数字、分子、账户，无关紧要；结构是：在集合中搜索补数 → 哈希表查找。

    大白话

    不管对象叫数字、分子还是账户，核心都是“找另一个能补到目标的值”，所以可以用同一套哈希查找思路。

    • 因此本章通过直觉讲模式（patterns through intuition），而非靠重复讲解题答案。对每种模式，我们解释：
      • 问题的哪种结构性质（structural property）提示该模式，已排序输入 → 双指针；子数组约束 → 滑动窗口；最优子结构 + 重叠子问题 → DP。
      • 模式为什么有效（why the pattern works），即数学或逻辑推理，而不只是“它能得到正确答案”。
      • 如何调整（how to adapt it），通过展示同一核心思想在不同语境中的简单、中等和困难变体。

    大白话

    学算法不能只看代码，还要知道什么信号提示某种模式、为什么它正确，以及题目变形后怎么调整。

    • 当你真正理解滑动窗口为何有效，约束的单调性意味着扩张/收缩就足够，你就能将它用在任何同类结构的问题上，即使从未见过。若只记住“无重复字符的最长子串”的代码，题目一变你就无从下手。

    大白话

    理解“窗口为什么能移动”比背某一道题的代码更有用，换输入和限制后仍能重新写出来。

    • 实际策略：
      1. 学习模式（Learn the pattern），即本章。
      2. 在伪装题中练习识别（Practise recognising it），每节结尾的 NeetCode take-home。
      3. 在时间压力下练习实现（Practise implementing it）。
      4. 面试中：读题 → 剥离语境 → 识别模式 → 实现。

    大白话

    实战顺序就是先学套路，再练识别，最后练速度；做题时先判断结构，不要一上来就敲代码。

    大 O 表示法¶

    • 称算法“快”或“慢”时，需要精确的度量方式。大 O 表示法（Big O notation）描述算法运行时间，或空间使用量，随输入规模 \(n\) 增长的方式，忽略常数因子和低阶项。

    大白话

    大 O 不关心今天跑了几毫秒，而关心数据变大后，耗时会按什么速度增长。

    • 形式定义：\(f(n) = O(g(n))\) 表示存在常数 \(c > 0\) 和 \(n_0\)，使得 \(f(n) \leq c \cdot g(n)\) 对所有 \(n \geq n_0\) 均成立。通俗说：在大输入下，\(f\) 的增长不快于 \(g\)。

    大白话

    只要输入足够大，算法的实际成本能被某个常数倍的 \(g(n)\) 稳稳压住，就可以说它是 \(O(g(n))\)。

    • 为什么忽略常数？因为 \(2n\) 算法与 \(5n\) 算法都是 \(O(n)\)，它们以相同方式扩展。换更快的计算机，常数会变，扩展规律不会。大 O 捕捉与硬件无关的问题内在（intrinsic）难度。

    大白话

    换电脑会改变常数，但不会改变“数据翻十倍要多做多少量级工作”；大 O 看的是这个长期趋势。

    增长率层级¶

    • 从最快到最慢：
    大 O 名称 示例 \(n = 10^6\) 时的操作数
    \(O(1)\) 常数 数组访问、哈希查找 1
    \(O(\log n)\) 对数 二分搜索 20
    \(O(n)\) 线性 线性扫描、单层循环 \(10^6\)
    \(O(n \log n)\) 线性对数 归并排序、高效排序 \(2 \times 10^7\)
    \(O(n^2)\) 二次 嵌套循环、暴力枚举数对 \(10^{12}\)（太慢）
    \(O(n^3)\) 三次 三层嵌套循环、矩阵乘法 \(10^{18}\)（远远太慢）
    \(O(2^n)\) 指数 全部子集、暴力回溯 \(10^{301030}\)（不可能）
    \(O(n!)\) 阶乘 全部排列 荒谬

    大白话

    表格越往下，输入稍微变大，工作量就暴涨得越厉害；这能帮助你先排除明显不可能的方案。

    • 经验法则（rule of thumb）：现代计算机每秒大约执行 \(10^8\)–\(10^9\) 个简单操作。若时限为 1 秒：
      • \(O(n)\) 对 \(n \leq 10^8\) 可行。
      • \(O(n \log n)\) 对 \(n \leq 10^7\) 可行。
      • \(O(n^2)\) 对 \(n \leq 10^4\) 可行。
      • \(O(2^n)\) 对 \(n \leq 25\) 可行。

    大白话

    这些数字只是估算尺，不是保证；它们的用途是快速判断“这个复杂度大概能不能过时限”。

    • 该表立即告诉你方法是否够快。若 \(n = 10^5\) 而方案为 \(O(n^2)\)，就有 \(10^{10}\) 次操作，太慢，必须使用更好的算法。

    大白话

    看到 \(n=10^5\) 却写出 \(O(n^2)\)，基本就说明需要换思路，而不是继续优化几行代码。

    如何分析大 O¶

    • 遍历 \(n\) 个元素的单层循环：\(O(n)\)。
    total = 0
for x in arr:   # n iterations
    total += x   # O(1) per iteration
# Total: O(n)

    大白话

    循环把每个元素看一遍，数据有多少就做多少次，所以是线性复杂度。

    • 嵌套循环：相乘迭代次数。
    for i in range(n):       # n iterations
    for j in range(n):   # n iterations each
        process(i, j)    # O(1)
# Total: O(n^2)

    大白话

    外层每跑一次，内层又完整跑一遍；两层各有 \(n\) 次，就乘成 \(n^2\)。

    • 每次减半的循环：\(O(\log n)\)。每轮将问题规模减半，因此需 \(\log_2 n\) 轮。
    i = n
while i > 0:
    process(i)
    i //= 2
# Total: O(log n)

    大白话

    每次砍掉一半，数据再大也只需少量几轮；这就是对数增长。

    • 内层依赖外层的嵌套循环：
    for i in range(n):
    for j in range(i):   # j goes from 0 to i-1
        process(i, j)
# Total: 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = O(n^2)

    大白话

    虽然内层次数不是固定的，但总次数仍是 0 到 \(n-1\) 的累加，量级还是 \(n^2\)。

    • 递归（Recursive）：写出并求解递推关系，第 13 章讨论过主定理。例如归并排序：\(T(n) = 2T(n/2) + O(n) = O(n \log n)\)。

    大白话

    递归算法要把“自己调用自己”的成本写成递推式，再求出整体增长速度。

    常见陷阱¶

    • 隐藏循环（Hidden loops）：Python 中 x in list 是 \(O(n)\)，线性扫描，而 x in set 是 \(O(1)\)。在循环内对列表使用 in，复杂度是 \(O(n^2)\) 而不是 \(O(n)\)。

    大白话

    有些看起来像一条语句的操作内部也会循环；要看清容器的查找成本，不能只数表面上的 for。

    # BAD: O(n^2) — "in" on a list is O(n)
for x in arr:
    if x in another_list:
        process(x)

# GOOD: O(n) — convert to set first
another_set = set(another_list)
for x in arr:
    if x in another_set:
        process(x)
    • 字符串拼接（String concatenation）：Python 中 s += c 每次都会复制完整字符串。若在 \(n\) 次循环中执行，复杂度为 \(O(1 + 2 + \cdots + n) = O(n^2)\)。

    大白话

    循环里反复拼接字符串会一遍遍复制旧内容，最好先收集片段，最后一次性合并。

    • 排序主导（Sorting dominance）：算法先排序，\(O(n \log n)\)，再线性扫描，\(O(n)\)，总复杂度为 \(O(n \log n)\)，排序占主导。

    大白话

    总复杂度取更慢的那一项；排序后的线性扫描不会把 \(O(n \log n)\) 变成更差的复杂度。

    • 摊销复杂度（Amortised complexity）：有些操作偶尔昂贵、平均却很便宜。动态数组 append 的摊销复杂度是 \(O(1)\)，因为罕见的 \(O(n)\) 扩容成本分摊给了 \(n\) 次廉价 append。不要把摊销 \(O(1)\) 与最坏情况 \(O(1)\) 混为一谈。

    大白话

    动态数组偶尔扩容会很贵，但把这次成本平均到很多次追加上，长期每次仍近似常数；这不等于每一次都保证 \(O(1)\)。

    空间复杂度¶

    • 空间复杂度遵循相同的大 O 规则，只是作用于内存使用而不是时间。

    大白话

    空间复杂度问的是“数据变大时额外占多少内存”，计算方法和时间复杂度类似。

    • 原地（in-place）算法使用 \(O(1)\) 额外空间，不计输入。快速排序使用 \(O(\log n)\) 空间，递归栈深度；归并排序使用 \(O(n)\)，合并时的临时数组。

    大白话

    原地算法尽量在原数组里改，省内存；但递归栈和临时数组也要算进额外空间。

    • 递归栈（Recursion stack）：每次递归调用都占用栈空间。深度为 \(n\) 的递归使用 \(O(n)\) 空间，即便每次调用都不分配额外内存。这正是含 \(n\) 个节点图上的递归 DFS 使用 \(O(n)\) 空间的原因。

    大白话

    每深入一层递归，就要多保存一份现场；递归很深时，光调用栈就可能占满内存。

    • 面试时应始终说明时间和空间复杂度。\(O(n)\) 时间、\(O(n)\) 空间的方案通常可接受，\(O(n)\) 时间、\(O(1)\) 空间则更好。面试官可能要求你优化其中之一。

    大白话

    写完算法别只说“能跑”，还要明确它花多少时间和内存，以及是否能在约束下接受。

    递归¶

    • 递归（Recursion）指函数调用自身来解决同一问题的更小实例。对具有递归结构的问题，树、嵌套结构、分治和数学序列，它最自然。

    大白话

    递归就是把“大问题”交给同样的函数去处理更小版本，直到小到可以直接回答。

    • 每个递归函数有两部分：
      1. 基例（Base case）：可直接求解的最小实例，不使用递归。这会停止递归。
      2. 递归情形（Recursive case）：将问题拆为更小子问题，递归求解，并合并结果。

    大白话

    基例负责刹车，递归情形负责把问题变小；少任何一个，递归都可能无限进行或答不对。

    示例：阶乘¶

    def factorial(n):
    if n <= 1:        # base case
        return 1
    return n * factorial(n - 1)  # recursive case
    • factorial(4) 的执行过程：
      • factorial(4) 调用 factorial(3)。
      • factorial(3) 调用 factorial(2)。
      • factorial(2) 调用 factorial(1)。
      • factorial(1) 返回 1，基例。
      • factorial(2) 返回 2 * 1 = 2。
      • factorial(3) 返回 3 * 2 = 6。
      • factorial(4) 返回 4 * 6 = 24。

    大白话

    阶乘递归先一路往下拆，到了 1 再一层层返回；每层把自己的数字乘回结果。

    • 每次调用都压入调用栈（call stack）。栈在到达基例前不断增长，随后每次调用返回时展开。递归过深时，例如 Python 中的 factorial(1000000)，栈会溢出，RecursionError。Python 默认递归深度限制为 1000。

    大白话

    递归调用越深，保存的现场越多；深到一定程度就会栈溢出，所以递归深度必须有边界。

    如何递归地思考¶

    • 关键思维转变是：相信递归（trust the recursion）。编写递归函数时，假设递归调用能够为较小子问题返回正确答案。你只需：
      1. 处理基例。
      2. 将问题拆成更小部分。
      3. 合并结果。

    大白话

    不要试图在脑中跟完所有层；只要证明“小问题正确时，我这一步能把它合成大问题正确答案”。

    • 无需在脑中追踪每一次递归调用。这就像试图通过手动执行循环的每次迭代来理解循环。应验证的是：“若递归调用为较小输入给出正确答案，我的合并步骤能否为完整输入给出正确答案？”

    大白话

    递归的核心是局部证明：相信子调用，专注当前节点怎样处理和合并结果。

    示例：链表上的递归¶

    • 递归反转链表：
    def reverse(head):
    if not head or not head.next:   # base case: 0 or 1 nodes
        return head

    new_head = reverse(head.next)   # reverse the rest
    head.next.next = head           # point the next node back to me
    head.next = None                # I am now the tail
    return new_head
    • 相信递归：reverse(head.next) 会正确反转链表余下部分，并返回新的头节点。我们只需将当前节点接到结尾。

    大白话

    先让递归把后面的链表反转好，再把当前节点接到尾巴；这就是“相信子问题”的具体用法。

    示例：树上的递归¶

    • 计算二叉树高度：
    def height(root):
    if not root:           # base case: empty tree has height 0
        return 0
    left_h = height(root.left)    # height of left subtree
    right_h = height(root.right)  # height of right subtree
    return 1 + max(left_h, right_h)  # this node adds 1 level
    • “对左边递归、对右边递归、合并结果”这一模式解决了绝大多数树问题，见第 03 节。

    大白话

    树的每个节点只需问左右子树的答案，再按题意合并；这是遍历树题最常见的骨架。

    递归与迭代¶

    • 每个递归算法均可转换为迭代算法，使用显式栈或循环。迭代避免调用栈开销和栈溢出风险。

    大白话

    递归栈也可以自己用数据结构模拟；这样更可控，但代码通常更啰嗦。

    • 何时偏向递归：问题有自然递归结构，树、嵌套数据、分治，递归解更整洁且更易推理。

    大白话

    如果问题本身就是“一层套一层”或“分成同类小块”，递归通常最顺手。

    • 何时偏向迭代：递归深度可能很大，例如处理含 \(10^6\) 节点的链表，迭代可避免栈溢出。

    大白话

    数据可能很深时，用循环更稳，避免因为调用层数太多把栈耗尽。

    • 尾递归（Tail recursion）：若递归调用是函数中的最后操作，递归调用返回后不再做任何工作，则为尾递归。部分语言，Scheme、Scala，会优化尾调用，只用常数栈空间。Python不会（does not）优化尾调用，因此 Python 中尾递归仍使用 \(O(n)\) 栈空间。

    大白话

    尾递归理论上可以像循环一样省栈，但 Python 不做这种优化，所以在 Python 里仍要承担深递归风险。

    常见陷阱¶

    陷阱 示例 修复
    缺少基例 无限递归 → 栈溢出 始终定义停止条件
    基例错误 递归分解中的 off-by-one 用最小输入测试，0、1、2
    未缩小问题 f(n) 调用 f(n) 而非 f(n-1) 确保子问题严格变小
    重复计算 斐波那契：f(n) = f(n-1) + f(n-2) 指数级重复 使用记忆化，→ DP
    Python 递归限制 factorial(10000) 崩溃 使用 sys.setrecursionlimit 或转为迭代

    回溯¶

    • 回溯（Backtracking）是一种系统探索所有可能解的方法：逐步构建解，并放弃不可能导向有效答案的部分解。

    大白话

    回溯就是边做选择边试探；一旦发现这条路不可能成功，就退回上一步换路。

    • 可以把它想成走迷宫。每个岔路口选择一条路；撞到死路时，回到上一个岔路口，尝试另一条路。不会从起点重来，而是回溯（backtrack）到最近的决策点。

    大白话

    回溯像走迷宫时记住最近的岔路口，不必每次都从入口重走。

    三个步骤¶

    每个回溯算法遵循相同模式：

    1. 选择（Choose）：选择一个候选项来扩展当前部分解。
    2. 探索（Explore）：递归尝试从该候选项构建完整解。
    3. 撤销选择（Unchoose）：撤销选择，回溯，并尝试下一个候选项。

    大白话

    回溯模板就是“选一个、往下试、回来撤销”；撤销是为了让下一条分支看到干净的状态。

    def backtrack(state, choices, result):
    if is_complete(state):
        result.append(state.copy())
        return

    for choice in choices:
        if is_valid(choice, state):
            state.add(choice)           # 1. choose
            backtrack(state, choices, result)  # 2. explore
            state.remove(choice)        # 3. unchoose (backtrack)
    • 撤销选择（unchoose）这一步将回溯与普通递归区分开来。没有它，状态会累积所有选择，无法探索替代路径。

    大白话

    如果不把刚才的选择恢复掉，后续分支会误以为那些东西仍然被选中，结果就会串味。

    何时使用回溯¶

    • 问题要求枚举全部有效配置（enumerate all valid configurations）：全部排列、全部子集、全部有效安排，例如 N 皇后。
    • 问题要求找到任一有效配置（find any valid configuration）：数独求解、迷宫寻路。
    • 搜索空间很大，但可剪枝（pruned）：大部分部分解可在深入探索前提前拒绝。

    大白话

    当你需要列出所有答案、找一个可行答案，或能很早排除大量错误路线时，就该考虑回溯。

    剪枝如何使它变快¶

    • 不剪枝时，回溯探索每种可能组合，复杂度为指数级。剪枝（Pruning）会提早切断分支：
    for choice in choices:
    if not is_valid(choice, state):
        continue  # PRUNE: skip this entire subtree

    state.add(choice)
    backtrack(state, choices, result)
    state.remove(choice)

    大白话

    剪枝就是发现当前部分解已经不可能成功时立即停下，不再浪费时间探索它的整棵子树。

    • 在 N 皇后问题，第 05 节，中，放置皇后前检查列和对角线冲突，可将搜索树从 \(n^n\) 剪至大约 \(n!\) 个候选。对 \(n = 8\)，即从 1600 万降至 4 万。良好的剪枝让指数算法在中等 \(n\) 下可行。

    大白话

    好的约束检查能把“几乎所有组合”砍掉，只留下少量有希望的候选，因此指数算法才可能处理小到中等规模。

    生成全部子集，最简单的回溯¶

    def subsets(nums):
    result = []

    def backtrack(start, path):
        result.append(path[:])  # every partial solution is a valid subset

        for i in range(start, len(nums)):
            path.append(nums[i])        # choose
            backtrack(i + 1, path)       # explore (i+1: no reuse)
            path.pop()                   # unchoose

    backtrack(0, [])
    return result

    • 对 [1, 2, 3]，递归树为：

      • [] → [1] → [1,2] → [1,2,3]，回溯，→ [1,3]，回溯，→ [2] → [2,3]，回溯，→ [3]。

    • 树中每个节点都是对 backtrack 的一次调用。每个叶节点，及中间节点，产生一个子集。子集总数：\(2^n\)。

    大白话

    每个元素都有“选或不选”两条路，所以 \(n\) 个元素自然产生 \(2^n\) 个子集。

    生成全部排列¶

    def permutations(nums):
    result = []

    def backtrack(path, remaining):
        if not remaining:
            result.append(path[:])
            return

        for i in range(len(remaining)):
            path.append(remaining[i])                    # choose
            backtrack(path, remaining[:i] + remaining[i+1:])  # explore
            path.pop()                                   # unchoose

    backtrack([], nums)
    return result
    • 排列总数：\(n!\)。每个排列构造 remaining 需 \(O(n)\) 工作，因此总复杂度为 \(O(n \cdot n!)\)。

    大白话

    排列数量本身就是阶乘级，此外每次复制剩余列表还要花 \(O(n)\)，所以总成本更高。

    常见陷阱¶

    陷阱 示例 修复
    忘记复制路径 result.append(path)，所有条目共享同一列表 result.append(path[:]) 或 path.copy()
    不回溯，撤销选择 状态持续增长，后续候选看到过期状态 递归调用后始终 path.pop() 或 state.remove()
    循环起点错误 子集重复，或排列有非预期复用 使用 start 参数避免重访早先索引
    跳过剪枝 探索明显无效的分支 在递归调用前添加 if not is_valid: continue

    动态规划¶

    • 动态规划（Dynamic programming, DP）是针对重复求解相同子问题的优化技术。DP 不重复计算，而是为每个子问题求解一次并保存结果。

    大白话

    DP 的核心是“算过的结果记下来”，以后再遇到同一个子问题直接拿，不重新算。

    • 当问题具备两个性质时适用 DP：
      1. 最优子结构（Optimal substructure）：最优解可由子问题的最优解构建。
      2. 重叠子问题（Overlapping subproblems）：同样的子问题在递归中多次出现。

    大白话

    只有“最优答案能由小答案拼出”且“小问题会反复出现”时，缓存才真正有价值。

    斐波那契动机¶

    • 朴素递归的斐波那契：
    def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

    • 对 fib(5)，递归树为：

      • fib(5) 调用 fib(4) 与 fib(3)。
      • fib(4) 调用 fib(3) 与 fib(2)。
      • fib(3) 被计算两次，fib(2) 被计算三次。

    • 这是 \(O(2^n)\)，因为树在每层分叉，而且大多数分支重复计算相同值。对 fib(50)，需超过 \(10^{15}\) 次操作，不可行。

    大白话

    朴素递归把同一个数字算很多遍，输入稍大就爆炸；问题不在公式，而在重复劳动。

    • 使用记忆化（memoisation），自顶向下 DP：
    def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]
    • 此时 fib(3) 只计算一次并保存，后续调用直接查找。总计：\(O(n)\) 时间、\(O(n)\) 空间。

    大白话

    记忆化保留递归写法，但给每个输入配缓存；每个状态只真正计算一次。

    • 使用制表法（tabulation），自底向上 DP：
    def fib_tab(n):
    if n <= 1:
        return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]
    • 时间同为 \(O(n)\)，但它自底向上构建解，不使用递归。每个值只依赖前两个值，因此可进一步优化至 \(O(1)\) 空间。

    大白话

    制表法从最小答案开始按顺序填表，避免递归栈；只保留最近需要的值时还能省掉整张表。

    DP 步骤¶

    对任意 DP 问题，遵循以下步骤：

    1. 定义状态（Define the state）：dp[i]，或 dp[i][j]，代表什么？这是最难的一步。状态必须包含做出最优决策所需的充分信息。
    2. 写出递推式（Write the recurrence）：dp[i] 如何与更小子问题相关？这就是状态转移公式。
    3. 确定基例（Identify the base case）：哪些最小子问题可直接求解？
    4. 确定迭代顺序（Determine the iteration order）：哪些子问题必须先于哪些求解？自底向上时，以确保依赖已解决的顺序迭代；自顶向下时，递归自动完成。
    5. 优化空间（Optimise space），可选：若 dp[i] 仅依赖前一行或前几项，不需要完整表。

    大白话

    DP 最难的是定义状态；状态说清楚后，转移、初值和计算顺序通常就能顺着依赖关系确定。

    示例：思考过程¶

    问题：给定正整数数组，求不相邻元素的最大和，House Robber。

    步骤 1，定义状态：dp[i] = 考虑元素 nums[0..i] 时的最大和。

    步骤 2，写出递推式：对元素 \(i\)，要么： - 跳过它：dp[i] = dp[i-1]，即不含元素 \(i\) 的最优和。 - 选取它：dp[i] = dp[i-2] + nums[i]，必须跳过元素 \(i-1\)，然后加上元素 \(i\)。

    因此：dp[i] = max(dp[i-1], dp[i-2] + nums[i])。

    步骤 3，基例：dp[0] = nums[0]，dp[1] = max(nums[0], nums[1])。

    步骤 4，迭代顺序：从左到右，每个状态依赖前两个状态。

    步骤 5，空间优化：只需最近两个值。

    大白话

    这个问题每次只依赖前两个结果，所以没必要保存全部历史，像只保留最近两张账单。

    def rob(nums):
    if len(nums) == 1:
        return nums[0]

    prev2, prev1 = nums[0], max(nums[0], nums[1])

    for i in range(2, len(nums)):
        curr = max(prev1, prev2 + nums[i])
        prev2, prev1 = prev1, curr

    return prev1

    如何识别 DP 问题¶

    • 问题要求最优值（optimum），最小成本、最大收益、最长序列，或计数（count），方法数量。
    • 问题在每一步有选择（choices at each step），选/跳过、向左/向右、是否使用该硬币，且全局最优答案依赖子问题最优答案。
    • 画递归树会发现重复子问题（repeated subproblems）。
    • 暴力解为指数级，但不同状态（distinct states）远少于递归调用数。

    大白话

    看到“最大、最小、多少种方法”、每步要做选择，并且不同路径反复到达同一状态，就要警惕 DP。

    DP 的类别¶

    • 一维 DP（1D DP）：状态依赖单个索引。示例：爬楼梯、House Robber、最大子数组。

    大白话

    一维 DP 通常沿着一个序列推进，每个位置记录到这里为止的最佳答案。

    • 二维 DP（2D DP）：状态依赖两个索引。示例：最长公共子序列，字符串 1 前 \(i\) 个字符和字符串 2 前 \(j\) 个字符的 dp[i][j]、编辑距离、网格路径问题。

    大白话

    两个索引表示两个维度的进度，例如同时走到两条字符串的某个位置。

    • 区间 DP（Interval DP）：状态为范围 dp[i][j]，代表 arr[i..j] 上的子问题。示例：矩阵链乘法、戳气球。

    大白话

    区间 DP 关注一段连续范围，常通过拆分点把大区间分成两个小区间。

    • 背包 DP（Knapsack DP）：状态是物品索引和容量。示例：0/1 背包、零钱兑换、子集和。

    大白话

    背包 DP 记录“看到哪些物品、还剩多少容量”，在取与不取之间找最优或计数。

    • 位掩码 DP（Bitmask DP）：状态包括表示已使用元素的位掩码。示例：TSP、指派问题。状态空间为 \(O(2^n \cdot n)\)，在 \(n \leq 20\) 时可行。

    大白话

    位掩码用二进制每一位表示某个元素是否用过，适合元素数量较少但组合状态很多的问题。

    自顶向下与自底向上¶

    自顶向下，记忆化 自底向上，制表
    实现 递归 + 缓存 迭代 + 表
    计算 仅实际需要的子问题 目标之前的全部子问题
    栈溢出风险 有，深递归 无
    空间优化 更难 更易，使用滚动数组
    编码难度 常更自然，写递归、加缓存 需要思考迭代顺序
    • 面试中，自顶向下通常更快写出。生产环境中，通常偏好自底向上以获得性能，无递归开销、缓存行为更好。

    大白话

    记忆化递归更贴近思路、写得快；制表法没有递归开销，通常更适合稳定的生产代码。

    常见陷阱¶

    陷阱 示例 修复
    状态定义错误 dp[i] 没有捕获足够信息来决策 增加维度，例如 dp[i][j] 而非 dp[i]
    缺少基例 dp[0] 错误 → 后续全错 手工验证基例
    迭代顺序错误 在依赖项之前计算 dp[i] 画依赖箭头并据此迭代
    未正确初始化 dp 最小化问题本应为无穷却使用 0 最小化用 float('inf')，最大化用 float('-inf')
    忘记“跳过”选项 总是选当前元素 递推式通常有 max(take, skip)
    可变默认参数 def f(memo={}) 在调用间共享缓存 def f(memo=None): if memo is None: memo = {}
    二维 DP off-by-one dp 为 1 索引却访问 text1[i] dp 大小为 (m+1) x (n+1)，访问 text1[i-1]

    融会贯通¶

    • 这四个概念构成一个递进关系：
      1. 大 O（Big O）告诉你一种方法是否足够快。
      2. 递归（Recursion）将问题拆为子问题。
      3. 回溯（Backtracking）是递归 + 选择 + 撤销，用于穷举搜索。
      4. DP是递归 + 缓存，用于重叠子问题上的优化。

    大白话

    大 O 先帮你判断代价，递归帮你拆题，回溯负责系统试错，DP 则把重复的递归结果缓存起来。

    • 遇到新问题时：
      • 估计输入规模 \(n\)。可接受何种大 O？
      • 若暴力解为指数级，且问题要求枚举/寻找配置：回溯，通过剪枝使其可行。
      • 若暴力解为指数级，问题要求最优值或计数，且存在重叠子问题：DP。
      • 若问题结构会将搜索空间减半：二分搜索（binary search）或分治（divide and conquer）。
      • 若问题是序列且对子数组有约束：滑动窗口（sliding window）或双指针（two pointers）。
      • 若问题需要快速查找：哈希表（hash map）。

    大白话
