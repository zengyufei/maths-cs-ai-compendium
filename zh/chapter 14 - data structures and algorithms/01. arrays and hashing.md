# 数组与哈希

*数组与哈希表是编程中最基础的两种数据结构。本节先讲解它们的底层工作方式，再通过难度递进的问题建立关键解题模式：双指针、滑动窗口、前缀和与基于哈希的查找，并在每一步说明常见陷阱。*

- 若你真正理解数组和哈希映射，就能解决约 40% 的编码面试问题。这两种结构无处不在，因为它们提供算法最常需要的两种能力：**快速按索引访问（fast indexed access）**，数组，和**快速按键查找（fast lookup by key）**，哈希映射。

- 本节讲模式，而非背答案。目标是当你遇到新问题时，能识别适用的模式及其原因，而不是试图回忆一个记住的解法。

## 数组

- **数组（array）**是连续内存块，元素存放在固定偏移处。访问元素 $i$ 的成本为 $O(1)$，因为地址就是 `base + i * element_size`。这是最快的数据访问方式，也是数组作为默认选择的原因。

- **动态数组（Dynamic arrays）**，Python 的 `list`、Java 的 `ArrayList`、C++ 的 `vector`，在存满时会自动增长。其策略是**摊销倍增（amortised doubling）**：数组满时，分配一个大小翻倍的新数组，并复制全部元素。复制成本为 $O(n)$，但发生得很少，每 $n$ 次插入才一次，因此每次插入的摊销成本为 $O(1)$。

- **缓存局部性（Cache locality）**解释了数组为何在实践中快，而不只是理论上快。元素连续存储，访问一个元素会把相邻元素加载至 CPU 缓存，第 13 章。遍历数组对缓存友好；沿链表指针跳转则不是。实践中的常数因子差异可达 10-100 倍。

| 操作 | 数组 | 动态数组 |
|-----------|-------|---------------|
| 按索引访问 | $O(1)$ | $O(1)$ |
| 追加 | 不适用 | 摊销 $O(1)$ |
| 在位置 $i$ 插入 | $O(n)$ | $O(n)$ |
| 在位置 $i$ 删除 | $O(n)$ | $O(n)$ |
| 搜索，未排序 | $O(n)$ | $O(n)$ |

- **陷阱（Pitfall）**：在数组中间插入或删除是 $O(n)$，因为后续全部元素都必须移动。若需要频繁在中间插入，应考虑链表或完全不同的方法。

## 字符串

- **字符串（string）**是字符数组。Python 字符串不可变：每次拼接都会创建新字符串。在循环中逐字符构建字符串是 $O(n^2)$，因为每次拼接都会复制至今的整个字符串。

```python
# BAD: O(n^2) string concatenation
s = ""
for c in characters:
    s += c  # copies entire string each time

# GOOD: O(n) using a list then join
parts = []
for c in characters:
    parts.append(c)
s = "".join(parts)
```

- **陷阱**：在 Python 循环中使用 `s += c` 是最常见的性能 bug 之一。始终先收集到列表，再使用 `.join()`。

- **编码（Encoding）**：ASCII 使用 7 位，128 个字符。**UTF-8** 是变长编码：ASCII 字符使用 1 字节，带重音字符使用 2 字节，中日韩字符使用 3 字节，emoji 使用 4 字节。题目若说“小写英文字母”，字母表大小就是 26，意味着可使用固定大小数组，而不是哈希映射。

## 哈希表

- **哈希表（hash table）**将键映射为值，平均查找、插入和删除时间均为 $O(1)$。它通过计算**哈希函数（hash function）** $h(key)$，将键转换为数组索引来工作。

- 哈希函数必须具备：**确定性（deterministic）**，相同键始终产生相同哈希、**均匀性（uniform）**，将键均匀分布到桶中，以及**计算快速（fast）**。

- 两个不同键哈希到相同索引时出现**冲突（Collisions）**。主要有两种策略：

    - **拉链法（Chaining）**：每个桶保存键值对的链表。冲突时追加至链表。最坏情况，全部键进入同一桶，为 $O(n)$；哈希函数良好时，平均情况为 $O(1)$。

    - **开放寻址（Open addressing）**：冲突时探测下一个空槽。**线性探测（Linear probing）**检查下一个槽、再下一个，依此类推。它对缓存友好，却会出现**聚集（clustering）**，连续占用槽过长。**罗宾汉哈希（Robin Hood hashing）**通过挪动“离家更近”的条目来降低方差。

- **装载因子（load factor）** $\alpha = n / m$，项目数/桶数，决定性能。当 $\alpha$ 超过阈值，通常为 0.75，时，表会**重新哈希（rehashes）**：分配更大的表并重新插入全部元素。成本为 $O(n)$，但发生频率低。

- **哈希映射（Hash maps）**，Python 的 `dict`、Java 的 `HashMap`，保存键值对。**哈希集合（Hash sets）**，Python 的 `set`、Java 的 `HashSet`，只保存键，用于快速成员测试。

| 操作 | 平均 | 最坏情况 |
|-----------|---------|------------|
| 查找 | $O(1)$ | $O(n)$ |
| 插入 | $O(1)$ | $O(n)$ |
| 删除 | $O(1)$ | $O(n)$ |

- **布隆过滤器（Bloom filters）**是节省空间的概率集合。它们可告诉你“肯定不在集合中”或“可能在集合中”，具有可调的假阳性率。它们使用 $k$ 个哈希函数和一个位数组，应用于数据库，避免读取不存在项目的磁盘、Web 缓存和拼写检查器。

- **何时使用哈希映射**：需要在 $O(1)$ 时间回答“我之前见过这个吗？”或“该键关联的计数/索引/值是什么？”时。若你为查找某物反复线性扫描，哈希映射几乎肯定能让它更快。

## 模式：哈希映射查找

- 最基本的模式：使用哈希映射以 $O(n)$ 扫描替代为 $O(1)$ 查找。

### 简单：两数之和

- **问题**：给定整数数组和目标值，返回两个数相加等于目标值的索引。

- **暴力法（Brute force）**为 $O(n^2)$：检查每一对。

- **模式洞见（Pattern insight）**：对每个数字 `num`，需要数组中某处存在 `target - num`。不扫描数组查找它，而是将已见数字存入哈希映射。

```python
def two_sum(nums, target):
    seen = {}  # value -> index
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
```

- **为什么有效**：单次遍历数组。对每个元素，哈希映射查找是 $O(1)$。总计：$O(n)$ 时间、$O(n)$ 空间。

- **陷阱**：检查补数前不要先将当前数字加入哈希映射，否则可能让一个元素与自身匹配。上面代码顺序正确：先检查，再插入。

### 中等：字母异位词分组

- **问题**：给定字符串列表，将字母异位词分组。`"eat"`、`"tea"`、`"ate"` 是一组。

- **模式洞见**：字母异位词拥有相同字符，只是顺序不同。排序每个字符串后，字母异位词会产生同一个排序键。将该排序键作为哈希映射键。

```python
from collections import defaultdict

def group_anagrams(strs):
    groups = defaultdict(list)
    for s in strs:
        key = tuple(sorted(s))  # or use character count tuple
        groups[key].append(s)
    return list(groups.values())
```

- **优化（Optimisation）**：排序每个字符串成本为 $O(k \log k)$，$k$ 为字符串长度。若要更快的键，可统计字符频率并用计数元组作为键：

```python
def group_anagrams_fast(strs):
    groups = defaultdict(list)
    for s in strs:
        count = [0] * 26
        for c in s:
            count[ord(c) - ord('a')] += 1
        groups[tuple(count)].append(s)
    return list(groups.values())
```

- 这对每个字符串是 $O(k)$，而非 $O(k \log k)$。字符计数元组是一种**规范形式（canonical form）**：同一组所有成员的表示相同。

- **陷阱**：Python 中列表不可哈希，不能作 `dict` 键，必须转换为元组。尝试 `groups[count].append(s)` 时，人们常在此出错。

### 困难：最长连续序列

- **问题**：给定无序数组，找出最长连续序列的长度，例如 `[100, 4, 200, 1, 3, 2]` → 4，因为有 `[1, 2, 3, 4]`。

- **暴力法**为 $O(n \log n)$：排序数组，再扫描连续段。

- **模式洞见**：将所有数字放入哈希集合，以 $O(1)$ 查找。对每个数，检查它是否为序列**开头（start）**，即 `num - 1` 不在集合中。若是，便计数序列向后延伸多远。

```python
def longest_consecutive(nums):
    num_set = set(nums)
    best = 0

    for num in num_set:
        # only start counting from the beginning of a sequence
        if num - 1 not in num_set:
            length = 1
            while num + length in num_set:
                length += 1
            best = max(best, length)

    return best
```

- **为什么是 $O(n)$**：内层 `while` 在所有迭代中合计最多运行 $n$ 次，每个数字最多访问两次：外层循环一次、作为 `while` 延伸一次。`if num - 1 not in num_set` 守卫确保只从序列开头计数。

- **陷阱**：没有 `if num - 1 not in num_set` 检查，就会从每个元素开始计数，最坏情况为 $O(n^2)$。例如 `[1, 2, 3, ..., n]` 会从每个起点扫描整段序列。

## 模式：双指针

- **双指针（two pointers）**模式使用两个在数组中移动的索引，通常从相对两端移动，或从同一端以不同速度移动。它适用于数组已排序，或需要比较数对的情形。

- **何时使用**：问题涉及数对、子数组或分区，且数组已经排序，或者排序后不会丢失所需信息。

### 简单：有效回文

- **问题**：判断字符串是否是回文，只考虑字母数字字符并忽略大小写。

- **模式**：一个指针在开头，一个在结尾；向内移动并比较字符。

```python
def is_palindrome(s):
    left, right = 0, len(s) - 1

    while left < right:
        # skip non-alphanumeric characters
        while left < right and not s[left].isalnum():
            left += 1
        while left < right and not s[right].isalnum():
            right -= 1

        if s[left].lower() != s[right].lower():
            return False

        left += 1
        right -= 1

    return True
```

- **陷阱**：忘记内层 `while` 中的 `left < right` 检查。没有它，在 `"!!!"` 这类全部非字母数字的字符串上，指针可能越界。

### 中等：三数之和

- **问题**：找出数组中和为零的所有唯一三元组。

- **模式**：排序数组。固定一个元素，再在剩余部分使用双指针，找出和等于固定元素相反数的数对。

```python
def three_sum(nums):
    nums.sort()
    result = []

    for i in range(len(nums) - 2):
        # skip duplicate fixed elements
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        left, right = i + 1, len(nums) - 1
        target = -nums[i]

        while left < right:
            total = nums[left] + nums[right]
            if total < target:
                left += 1
            elif total > target:
                right -= 1
            else:
                result.append([nums[i], nums[left], nums[right]])
                # skip duplicates
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1

    return result
```

- **为什么有效**：排序为 $O(n \log n)$。对每个固定元素，双指针扫描为 $O(n)$。总计 $O(n^2)$，对此问题已是最优，因为必须考虑所有数对。

- **陷阱**：处理重复项最难。若没有跳过重复的逻辑，固定元素和双指针结果都需要，就会返回重复三元组。`if i > 0 and nums[i] == nums[i-1]: continue` 这一行至关重要。

### 困难：接雨水

- **问题**：给定地形图，非负整数数组，计算下雨后能接住多少水。

- **模式洞见**：每个位置的水位由它左边最大高度和右边最大高度的较小者，减去当前位置高度，决定。两端双指针跟踪这些运行最大值。

```python
def trap(height):
    left, right = 0, len(height) - 1
    left_max, right_max = 0, 0
    water = 0

    while left < right:
        if height[left] < height[right]:
            if height[left] >= left_max:
                left_max = height[left]
            else:
                water += left_max - height[left]
            left += 1
        else:
            if height[right] >= right_max:
                right_max = height[right]
            else:
                water += right_max - height[right]
            right -= 1

    return water
```

- **为什么有效**：关键洞见是，若 `height[left] < height[right]`，位置 `left` 的水量由 `left_max` 限定，我们已知右边存在更高柱子，所以右边不可能是瓶颈。处理较短的一侧，可保证另一侧有更高柱子。

- **陷阱**：许多人先预计算 `left_max[i]` 和 `right_max[i]` 数组，这种做法正确，却使用 $O(n)$ 空间。双指针方案只用 $O(1)$ 空间。此外，在最大值更新中混淆 `>=` 与 `>` 会造成 off-by-one 的水量计算。

## 模式：滑动窗口

- **滑动窗口（sliding window）**模式维护一个连续窗口，随着迭代扩张和收缩。它适用于满足某个条件的子数组或子串问题。

- **何时使用**：问题要求满足约束的最长/最短子数组或子串，且窗口扩张/收缩具有单调性，即添加元素只会使约束更难或更容易满足，而不会两者皆可能。

- **模板（Template）**：

```python
def sliding_window(arr):
    left = 0
    state = ...  # window state (counts, sum, etc.)
    best = ...

    for right in range(len(arr)):
        # expand: add arr[right] to the window state
        update_state(state, arr[right])

        # contract: shrink from the left while constraint is violated
        while constraint_violated(state):
            remove_from_state(state, arr[left])
            left += 1

        # update answer
        best = max(best, right - left + 1)  # or min, depending on problem

    return best
```

### 简单：买卖股票的最佳时机

- **问题**：给定每日价格，找出一次买入和一次卖出所能获得的最大利润，买在卖之前。

- **模式**：跟踪至今的最低价格，窗口左边界，并计算每天的利润。

```python
def max_profit(prices):
    min_price = float('inf')
    max_profit = 0

    for price in prices:
        min_price = min(min_price, price)
        max_profit = max(max_profit, price - min_price)

    return max_profit
```

- 这是退化的滑动窗口：左指针，最低价，仅在出现新最低价时向前移动。$O(n)$ 时间、$O(1)$ 空间。

### 中等：无重复字符的最长子串

- **问题**：找出不含任何重复字符的最长子串长度。

- **模式**：移动 `right` 扩张窗口。发现重复字符时，从左收缩，直至移除重复。

```python
def length_of_longest_substring(s):
    char_index = {}  # character -> its most recent index
    left = 0
    best = 0

    for right, char in enumerate(s):
        if char in char_index and char_index[char] >= left:
            left = char_index[char] + 1  # jump past the duplicate

        char_index[char] = right
        best = max(best, right - left + 1)

    return best
```

- **为什么要 `char_index[char] >= left`**：该字符可能从当前窗口开始前就已存在映射中。没有这个检查，会为实际上不在当前窗口中的字符错误缩小窗口。

- **陷阱**：使用集合并从左逐个移除字符是正确的，却较慢。哈希映射方案直接跳到正确位置。

### 困难：最小覆盖子串

- **问题**：给定字符串 `s` 与 `t`，找出 `s` 中包含 `t` 全部字符的最小窗口。

- **模式**：扩张窗口直到包含全部所需字符，然后从左收缩以找到最小有效窗口。

```python
from collections import Counter

def min_window(s, t):
    if not t or not s:
        return ""

    need = Counter(t)       # characters we need and their counts
    have = 0                # how many unique characters we have in sufficient quantity
    required = len(need)    # how many unique characters we need

    left = 0
    best = (float('inf'), 0, 0)  # (length, left, right)

    window_counts = {}

    for right in range(len(s)):
        char = s[right]
        window_counts[char] = window_counts.get(char, 0) + 1

        # check if this character's count now meets the requirement
        if char in need and window_counts[char] == need[char]:
            have += 1

        # contract from the left while the window is valid
        while have == required:
            # update best
            if (right - left + 1) < best[0]:
                best = (right - left + 1, left, right)

            # remove leftmost character
            left_char = s[left]
            window_counts[left_char] -= 1
            if left_char in need and window_counts[left_char] < need[left_char]:
                have -= 1
            left += 1

    length, start, end = best
    return s[start:end + 1] if length != float('inf') else ""
```

- **陷阱**：`have` 计数器是关键优化。没有它，每一步都需将整个 `window_counts` 字典与 `need` 比较，即每一步 $O(|\text{unique chars}|)$。`have` 使有效性检查为 $O(1)$。

- **陷阱**：检查 `window_counts[char] == need[char]`，而非 `>=`，可确保每个字符只将 `have` 加一。若使用 `>=`，会重复计数。

## 模式：前缀和

- **前缀和（prefix sum）**数组保存累积和：`prefix[i] = sum(arr[0:i])`。在 $O(n)$ 内构建后，任意子数组和可在 $O(1)$ 内计算：`sum(arr[l:r]) = prefix[r] - prefix[l]`。

```python
def build_prefix(arr):
    prefix = [0] * (len(arr) + 1)
    for i in range(len(arr)):
        prefix[i + 1] = prefix[i] + arr[i]
    return prefix

# sum of arr[l:r] (inclusive l, exclusive r)
def range_sum(prefix, l, r):
    return prefix[r] - prefix[l]
```

- **何时使用**：问题涉及多次子数组和查询，或寻找具有特定和的子数组。

### 简单：区间和查询

- **问题**：给定数组，回答多次“从索引 $l$ 到 $r$ 的和是多少？”查询。

- 不用前缀和：每次查询为 $O(n)$；使用前缀和：预计算 $O(n)$，之后每次查询 $O(1)$。

### 中等：和为 K 的子数组

- **问题**：统计和为 $k$ 的连续子数组数量。

- **模式洞见**：索引 $l$ 到 $r$ 的子数组和为 `prefix[r+1] - prefix[l]`。希望它等于 $k$，因此 `prefix[l] = prefix[r+1] - k`。每个位置使用哈希映射统计有多少早先前缀和等于 `current_prefix - k`。

```python
def subarray_sum(nums, k):
    count = 0
    prefix = 0
    prefix_counts = {0: 1}  # empty prefix sum

    for num in nums:
        prefix += num
        # how many earlier prefix sums equal prefix - k?
        count += prefix_counts.get(prefix - k, 0)
        prefix_counts[prefix] = prefix_counts.get(prefix, 0) + 1

    return count
```

- 它结合前缀和与哈希映射查找：$O(n)$ 时间、$O(n)$ 空间。

- **陷阱**：忘记初始化 `prefix_counts = {0: 1}`。空前缀，任何元素前，的和是 0；没有它会漏掉从索引 0 开始的子数组。

### 困难：除自身以外数组的乘积

- **问题**：给定数组，返回一个数组，其中每个元素是其他全部元素的乘积。不能使用除法。

- **模式**：从左构建前缀乘积，从右构建后缀乘积。每个位置的答案为 `left_product * right_product`。

```python
def product_except_self(nums):
    n = len(nums)
    result = [1] * n

    # left pass: result[i] = product of nums[0..i-1]
    prefix = 1
    for i in range(n):
        result[i] = prefix
        prefix *= nums[i]

    # right pass: multiply by product of nums[i+1..n-1]
    suffix = 1
    for i in range(n - 1, -1, -1):
        result[i] *= suffix
        suffix *= nums[i]

    return result
```

- $O(n)$ 时间、$O(1)$ 额外空间，输出数组不计。它使用输出数组保存中间前缀乘积，并在第二次遍历时乘入后缀乘积。

- **陷阱**：数组包含零时，基于除法的方法会失败。此方法从不除法，故可正确处理零。

## 常见陷阱汇总

| 陷阱 | 示例 | 修复 |
|---------|---------|-----|
| 窗口大小 off-by-one | `right - left` 与 `right - left + 1` | 写出一个 2 元素示例 |
| Python 可变默认值 | `def f(seen={})` 在调用间共享状态 | 使用 `def f(seen=None)` |
| 循环中的字符串拼接 | Python 中 `s += c` 为 $O(n^2)$ | 使用 `list.append` + `"".join` |
| 忘记前缀和 `{0: 1}` | 漏掉索引 0 开始的子数组 | 始终用空前缀初始化 |
| 检查前先写哈希映射 | Two Sum：检查补数前加入 `num` | 先检查，再插入 |
| 未处理重复 | Three Sum 返回重复三元组 | 跳过连续相等值 |
| 整数溢出 | C++/Java 中大数组之和 | 使用 `long` 或检查边界 |
