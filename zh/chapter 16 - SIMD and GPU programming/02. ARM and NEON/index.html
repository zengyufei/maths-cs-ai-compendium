    ARM 与 NEON¶

    ARM 处理器为每台智能手机、大多数平板、Apple 笔记本以及越来越多的数据中心服务器提供动力。本节涵盖 ARM 架构、通过 C++ 内建函数进行 NEON SIMD 编程、可伸缩向量处理 SVE/SVE2、Apple Silicon 特性与实用的向量化内核示例。

    • 如果你拥有 iPhone、MacBook，或使用 AWS Graviton 实例，就在运行 ARM。ARM 的能效使其主导移动端和嵌入式领域，并在服务器与机器学习推理中日益具备竞争力。理解 ARM SIMD，才能让代码在大多数人实际使用的硬件上快速运行。

    • 要看生产环境中 ARM SIMD 内核的实例，请参见 Cactus，一款面向移动设备和可穿戴设备的低延迟 AI 引擎：github.com/cactus-compute/cactus。Cactus 为注意力、KV-cache 量化和分块预填充实现了自定义 ARM NEON 与 NPU 加速内核，以比其他引擎低 10 倍的 RAM 获得 ARM CPU 上最快的推理。其三层架构（Engine → Graph → Kernels）具体展示了本节 SIMD 概念如何用于构建生产级机器学习基础设施。

    大白话

    ARM 不只是手机芯片，Mac 和许多云服务器也在用它。移动和边缘端内存、电量都紧张，所以把常用张量计算写成高效 NEON 内核很有实际价值。

    ARM 架构基础¶

    • ARM 是一种 RISC（精简指令集计算机）架构（第 13 章），关键特性如下：

      • 加载-存储架构：算术指令只操作寄存器，从不直接操作内存。要将内存中的两个数相加，必须：（1）加载到寄存器；（2）相加寄存器；（3）将结果写回内存。它比 x86（可在一条指令中将寄存器和内存地址相加）简单，但能实现更干净的流水线。

      • 定长指令：每条 ARMv8（AArch64）指令恰好为 32 位。这使译码快速且可预测，不同于长度可为 1 至 15 字节的 x86 变长指令。

      • 32 个通用寄存器（x0-x30，每个 64 位），外加栈指针（sp）和零寄存器（xzr）。相比 x86 的 16 个通用寄存器，更多寄存器意味着更少内存访问和更快代码。

      • 用于 NEON 与浮点操作的 32 个 SIMD/浮点寄存器（v0-v31，每个 128 位）。

    大白话

    ARM 规定了清楚的规则：先把数据拿进寄存器，再计算，最后写回内存。更多寄存器能让 CPU 暂存更多中间结果，少来回访问较慢的内存。

    // ARM assembly (just to see the flavour -- you will use intrinsics, not assembly)
// Add two registers
add x0, x1, x2    // x0 = x1 + x2

// Load from memory
ldr x0, [x1]      // x0 = *x1 (load 64 bits from address in x1)

// NEON: add four floats
fadd v0.4s, v1.4s, v2.4s  // v0 = v1 + v2 (four 32-bit floats)
    • 你不需要写汇编，而要使用内建函数（intrinsics）：一一映射到特定指令的 C/C++ 函数。编译器负责寄存器分配、调度和其他底层细节。

    大白话

    内建函数是“用 C++ 写的指令开关”。你明确要求使用某条 NEON 指令，但仍让编译器处理寄存器和机器码细节。

    NEON：128 位 SIMD¶

    • NEON 是 ARM 的 SIMD 扩展。每个 NEON 寄存器宽 128 位，可容纳：
    数据类型 每寄存器元素数 表示法
    float32 4 float32x4_t
    float16 8 float16x8_t
    int32 4 int32x4_t
    int16 8 int16x8_t
    int8 16 int8x16_t
    • 128 位比 x86 的 AVX（256 位）或 AVX-512（512 位）窄，但 ARM 以优异能效和广泛普及度弥补了它。

    大白话

    NEON 一次处理的 float32 数量不如宽 AVX 多，但它几乎存在于现代 ARM 设备中，并且很省电。能在更多目标设备上稳定发挥，往往比单次理论峰值更重要。

    NEON 内建函数：基础¶

    • NEON 内建函数遵循命名约定：v[operation][qualifier]_[type]
    #include <arm_neon.h>

// Load 4 floats from memory into a NEON register
float32x4_t a = vld1q_f32(ptr);        // vld1q = vector load 1, q = 128-bit (quad)

// Store 4 floats from a NEON register to memory
vst1q_f32(out_ptr, a);                   // vst1q = vector store 1, q = 128-bit

// Arithmetic
float32x4_t c = vaddq_f32(a, b);        // c = a + b (4 floats)
float32x4_t d = vmulq_f32(a, b);        // d = a * b (4 floats)
float32x4_t e = vfmaq_f32(c, a, b);     // e = c + a * b (fused multiply-add, 4 floats)

// Comparison (returns a mask: all 1s if true, all 0s if false)
uint32x4_t mask = vcgtq_f32(a, b);      // mask[i] = (a[i] > b[i]) ? 0xFFFFFFFF : 0

// Select elements based on mask (like numpy.where)
float32x4_t result = vbslq_f32(mask, a, b);  // result[i] = mask[i] ? a[i] : b[i]

// Reduce: sum all 4 elements to a scalar
float total = vaddvq_f32(a);             // total = a[0] + a[1] + a[2] + a[3]

    大白话

    这些函数名字虽然长，核心动作只有装载、计算、比较、选择和归约。把它们看成“对四个数字同时做同一件事”，读起来就容易很多。

    • vfmaq_f32（融合乘加）是机器学习最重要的 SIMD 指令。它用一条指令、一次舍入计算 \(c = c + a \times b\)，比先乘后加更准确。点积、矩阵乘法和卷积都由 FMA 构成。

    大白话

    FMA 把乘法和加法合成一次硬件动作，既少一条指令，也少一次中间舍入。矩阵乘法本质上大量重复这个动作，因此它是性能关键。

    实例：向量化点积¶

    • 点积是矩阵乘法的内层循环。下面先用标量 C++ 编写，再以 NEON 向量化。
    #include <arm_neon.h>

// Scalar dot product
float dot_scalar(const float* a, const float* b, int n) {
    float sum = 0.0f;
    for (int i = 0; i < n; i++) {
        sum += a[i] * b[i];
    }
    return sum;
}

// NEON-vectorised dot product
float dot_neon(const float* a, const float* b, int n) {
    float32x4_t sum_vec = vdupq_n_f32(0.0f);  // initialise 4 accumulators to 0

    int i = 0;
    for (; i + 4 <= n; i += 4) {
        float32x4_t va = vld1q_f32(a + i);     // load 4 elements from a
        float32x4_t vb = vld1q_f32(b + i);     // load 4 elements from b
        sum_vec = vfmaq_f32(sum_vec, va, vb);   // sum_vec += va * vb
    }

    // Reduce the 4 accumulators to a single scalar
    float sum = vaddvq_f32(sum_vec);

    // Handle remaining elements (if n is not a multiple of 4)
    for (; i < n; i++) {
        sum += a[i] * b[i];
    }

    return sum;
}

    大白话

    点积循环每次取 4 对数、同时相乘并累加，最后才把 4 个局部和合成一个结果。不能凑满 4 个的尾巴再用普通循环补上，这样不会漏数据。

    • 关键 C++ 概念：
      • const float*：指向只读 float 数据的指针。const 承诺不会经由该指针修改数据。
      • a + i：指针算术。a + i 指向数组的第 \(i\) 个元素，等同于 &a[i]。
      • 末尾的“清理循环”处理 \(n\) 不是 4 的倍数的情形。这是 SIMD 代码的通用模式：主体按向量块处理，余数用标量代码处理。

    大白话

    const float* 是只读数组地址，a + i 就是向后移动到第 i 个元素。固定宽度 SIMD 的常见模板是：大部分整块处理，最后几项单独收尾。

    • sum_vec 中为何有 4 个累加器：不是使用一个标量累加器，而是使用 4 个相互独立的累加器（每个 SIMD lane 一个）。这避免了数据依赖：每次迭代的 FMA 都依赖 sum_vec，而有 4 个独立 lane 时，CPU 可将 FMA 流水线化。最后再将 4 个部分和归约为一个值。

    大白话

    四个累加格子能轮流接收结果，不必让下一次计算死等同一个格子写完。先并行积累、最后求和，是隐藏 FMA 延迟的常见技巧。

    实例：向量化 ReLU¶

    #include <arm_neon.h>

void relu_neon(const float* input, float* output, int n) {
    float32x4_t zero = vdupq_n_f32(0.0f);

    int i = 0;
    for (; i + 4 <= n; i += 4) {
        float32x4_t x = vld1q_f32(input + i);
        float32x4_t result = vmaxq_f32(x, zero);  // max(x, 0) = ReLU
        vst1q_f32(output + i, result);
    }

    // Scalar cleanup
    for (; i < n; i++) {
        output[i] = input[i] > 0 ? input[i] : 0;
    }
}
    • vmaxq_f32 计算两个向量逐元素的最大值。一个向量全为零时，这正是 ReLU：没有分支、没有比较，只有一条指令。

    大白话

    ReLU 可以理解为每个数和 0 比大小。SIMD 同时比较四个数，而且不需要 if 跳转，规则整齐时硬件会跑得更顺。

    I8MM：整数矩阵乘法¶

    • I8MM（Int8 Matrix Multiply）是 ARMv8.6 扩展，增加了使用 INT32 累加的 INT8 矩阵乘法专用指令，恰好满足量化机器学习推理需求。

    大白话

    量化模型把数字压到 INT8 后，硬件能一次塞进更多值。I8MM 就是为这种低精度矩阵乘法准备的专用快捷通道，累加时仍用 INT32 防止很快溢出。

    • 核心指令是 SMMLA（Signed Matrix Multiply-Accumulate）：它接受两个 INT8 值的 8×2 块，并将结果累加到一个 INT32 的 2×2 块：
    #include <arm_neon.h>

// I8MM: multiply two 8-element INT8 vectors, accumulate into 4 INT32 results
// This computes a 2x2 tile of the output matrix from 2x8 x 8x2 input tiles
void matmul_i8mm_tile(const int8_t* A, const int8_t* B, int32_t* C) {
    // Load 8 bytes from A (2 rows of 4 elements, packed)
    int8x16_t va = vld1q_s8(A);   // 16 bytes = 2 rows × 8 elements
    int8x16_t vb = vld1q_s8(B);   // 16 bytes = 2 rows × 8 elements

    // Load existing accumulator (2x2 = 4 int32 values)
    int32x4_t acc = vld1q_s32(C);

    // I8MM instruction: acc += A_tile × B_tile^T
    // Computes 2×2 output from 2×8 × 8×2 inputs
    acc = vmmlaq_s32(acc, va, vb);  // THE I8MM instruction

    vst1q_s32(C, acc);
}

    大白话

    这段代码把小块矩阵装进寄存器，再用一条 I8MM 指令更新四个输出位置。它不是算完整大矩阵，而是高性能矩阵乘法里不断重复的一个小积木。

    • I8MM 为何重要：没有 I8MM 时，NEON 上的 INT8 matmul 需要扩宽乘法（vmull）再成对相加，每个输出元素需要多条指令；有了 I8MM，硬件会用一条指令完成 8 元素点积（2×8 × 8×2 = 2×2）。对 INT8 推理工作负载，这比普通 NEON 快 4 至 8 倍。

    大白话

    没有专用指令时，CPU 要自己拆开很多小步骤；I8MM 直接把这组步骤刻进硬件。量化推理常常因此获得数倍加速，同时减少内存占用。

    • 可用性：Apple M1+（所有 Apple Silicon）、ARM Cortex-A510/A710/X2+（ARMv9）、AWS Graviton3+。使用 #ifdef __ARM_FEATURE_MATMUL_INT8 检查。

    • 对机器学习推理来说，运行在 ARM 服务器（Graviton）或 Apple Silicon 上的 INT8 量化模型（第 18 章）能从 I8MM 获得巨大收益。ONNX Runtime 和 llama.cpp 等框架会在运行时检测 I8MM 并自动使用优化内核。

    大白话

    应用代码通常不用手动选择 I8MM；成熟框架会先检查设备是否支持，再换用对应内核。手写内核时才需要直接关注这个特性检测。

    SME 与 SME2：可伸缩矩阵扩展¶

    • SME（Scalable Matrix Extension）是 ARM 对 Intel AMX 和 NVIDIA Tensor Core 的回应：用于矩阵操作的专用硬件。SME2（ARMv9.2）进一步扩展了它。

    • SME 引入 ZA tile 寄存器：在硬件中存储的二维矩阵，最大为 SVL×SVL 字节（SVL 是流式向量长度，每维通常 128 至 512 位）。不同于 NEON 的一维向量、乃至 SVE 的一维可伸缩向量，SME 原生操作二维 tile。

    大白话

    NEON 把一排数字放进寄存器，SME 直接在芯片里保留一个二维小矩阵。矩阵乘法刚好不断更新这种二维小块，因此 SME 更贴近任务本身。

    • 编程模型有两种模式：
      • 普通模式：标准 ARM 执行，NEON 和 SVE 照常工作。
      • 流式 SVE 模式：通过 smstart 进入，启用 SME 指令。SVE 指令也可在该模式中工作，但可能使用不同寄存器宽度。
    #include <arm_sme.h>

// SME2: outer product accumulation for matrix multiply
// Accumulates A_col × B_row into the ZA tile register
void sme2_matmul_outer(const float* A_col, const float* B_row, int K) {
    // Enter streaming mode
    // smstart;  // (done via compiler intrinsic or inline asm)

    // Zero the ZA tile accumulator
    svzero_za();

    for (int k = 0; k < K; k++) {
        // Load a column of A and a row of B into SVE registers
        svfloat32_t a = svld1_f32(svptrue_b32(), &A_col[k * SVL]);
        svfloat32_t b = svld1_f32(svptrue_b32(), &B_row[k * SVL]);

        // Outer product: ZA += a × b^T
        // This accumulates an SVL×SVL tile in one instruction
        svmopa_za32_f32_m(0, svptrue_b32(), svptrue_b32(), a, b);
    }

    // Store the ZA tile to memory
    // svst1_za(...);

    // Exit streaming mode
    // smstop;
}
    • 关键概念：
      • svmopa（外积累加）：核心 SME 指令。它计算两个向量的完整外积并累加到 ZA tile。SVL=512 位（16 个 float）时，即一条指令完成 16×16 外积，共 256 次 FMA。
      • ZA tile：在流式模式内跨指令保持。将多个外积（每个 K 迭代一次）累加到同一 tile 中，构建完整的矩阵乘法 tile。
      • 流式模式：SME 指令仅在流式模式工作。进入/退出的开销意味着 SME 适用于持续的矩阵计算，而非短促操作。

    大白话

    SME 先进入专门的工作模式，再让许多外积持续累积在同一个 ZA tile 中。启动成本不小，所以它适合长时间算矩阵，不适合只算一下就结束的零碎操作。

    • SME2 新增内容：多向量操作（同时处理 2 或 4 个 SVE 向量）、额外 tile 操作，以及与普通模式更好的集成。

    • 可用性：ARM Neoverse V2（AWS Graviton4）和部分即将推出的移动芯片。截至 2026 年，Apple Silicon 尚未采用。SME 仍处早期，大多数机器学习框架还没有 SME 优化内核。

    • 演进路径：NEON（128 位向量、逐元素）→ I8MM（INT8 矩阵 tile）→ SVE（可伸缩向量）→ SME（可伸缩二维矩阵 tile）。每一代都让硬件更接近原生矩阵操作。

    大白话

    这条路线是在逐步把“矩阵乘法要靠很多标量指令拼出来”变成“硬件直接懂矩阵小块”。专用程度越高，理论效率越高，适用硬件也越少。

    SVE 与 SVE2：可伸缩向量扩展¶

    • NEON 宽度固定为 128 位。SVE（Scalable Vector Extension）引入向量长度无关（VLA）编程：只写一次代码，即可在任意向量宽度（128 至 2048 位）硬件上运行，硬件在运行时决定宽度。
    #include <arm_sve.h>

void add_sve(const float* a, const float* b, float* c, int n) {
    int i = 0;
    svbool_t pred = svwhilelt_b32(i, n);  // predicate: which lanes are active

    while (svptest_any(svptrue_b32(), pred)) {
        svfloat32_t va = svld1(pred, a + i);
        svfloat32_t vb = svld1(pred, b + i);
        svst1(pred, c + i, svadd_x(pred, va, vb));

        i += svcntw();  // advance by the hardware vector width (in 32-bit elements)
        pred = svwhilelt_b32(i, n);
    }
}

    大白话

    SVE 代码不假定一次一定处理 4 个或 8 个数，而是运行时询问机器实际宽度。谓词像每个位置的开关，最后一批不满时自动关掉多余位置。

    • 谓词寄存器（svbool_t）替代标量清理循环。每个 lane 都有谓词位：活动 lane 参与计算，非活动 lane 被掩蔽。svwhilelt_b32(i, n) 创建一个谓词，令对应 i, i+1, ..., n-1 的 lane 活动，因而自动处理尾部。

    • svcntw() 在运行时返回每个向量寄存器的 32 位元素数。256 位 SVE CPU 返回 8，512 位 SVE 返回 16，代码会自动适配。

    大白话

    同一份 SVE 程序在宽机器上每轮多走一些，在窄机器上每轮少走一些，但不需要重写循环边界。这就是“向量长度无关”的核心好处。

    • SVE 可用于 ARM Neoverse V1/V2（AWS Graviton3/4 和部分服务器芯片），尚未可用于 Apple Silicon。

    大白话

    ARM 是一套架构，不代表每台 ARM 机器都具备同样扩展。发布 SVE 或 SME 代码前，必须按目标芯片的实际能力编译并测试。

    Apple Silicon 特性¶

    • Apple M 系列芯片（M1、M2、M3、M4）基于 ARM，并有自定义微架构：

    • 性能核与能效核：P-core（Firestorm/Avalanche 等）用于重计算，E-core（Icestorm/Blizzard 等）用于后台任务。调度器将线程分配到合适类型的核心。

    • AMX（Apple Matrix eXtensions）：独立于 NEON 的专用矩阵乘法单元。AMX 未公开，Apple 未发布 ISA；但 Accelerate 框架在内部将其用于 BLAS 操作。Mac 上调用 np.dot 会经过 Accelerate 并使用 AMX。除逆向工程外，无法直接编程 AMX。

    • 统一内存：CPU 与 GPU 共享同一物理 RAM。其他系统必须经 PCIe（约 32 GB/s）将数据从 CPU 内存复制到 GPU 内存；Apple Silicon 不需要复制，GPU 直接读取 CPU 写入的同一块内存，消除了机器学习工作负载的主要瓶颈。

    • Neural Engine：16 核专用机器学习加速器，为 INT8 推理提供约 30 TOPS（每秒万亿次运算），由 Core ML 用于设备端推理。

    • Apple Silicon 上的机器学习：使用为统一内存架构设计的 MLX（Apple 机器学习框架）。PyTorch 也支持 MPS（Metal Performance Shaders）后端，但成熟度低于 CUDA。

    大白话

    Apple 芯片会把重任务分给性能核，轻任务分给能效核；CPU、GPU 又共享内存，所以本地推理很顺手。代价是不能直接使用 CUDA，工具链和兼容性要按 Metal/MLX 的现实来选。

    自动向量化¶

    • 编写 SIMD 内建函数很繁琐，编译器能否自动将代码向量化？

    • 可以，但有条件。现代编译器（GCC、Clang）可自动向量化简单循环：

    // The compiler CAN auto-vectorise this (with -O3 -march=native)
void add_auto(const float* a, const float* b, float* c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}

    大白话

    先写清楚的普通循环，编译器有时已经能替你变成 SIMD。这样代码更容易维护，性能也可能与手写内建函数接近。

    • 有助于自动向量化的模式：
      • 迭代次数已知的简单循环。
      • 迭代之间没有数据依赖（c[i] 不依赖 c[i-1]）。
      • 连续内存访问（无 scatter/gather）。
      • const 与 restrict 指针，告知编译器数组不重叠。
    // restrict tells the compiler: a, b, c point to non-overlapping memory
void add_restrict(const float* __restrict__ a,
                  const float* __restrict__ b,
                  float* __restrict__ c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}
    • 没有 restrict 时，编译器必须假设 c 可能与 a 或 b 重叠，写入 c[i] 可能改变 a[i+1]，从而阻止向量化。

    大白话

    restrict 是告诉编译器“这些数组不会指向同一块内存”的承诺。这个承诺必须是真的；若实际重叠却这样声明，结果可能错误。

    • 阻止自动向量化的模式：
      • 数据依赖：a[i] = a[i-1] + b[i]（每次迭代依赖前一次）。
      • 复杂控制流：循环内有 if（除非编译器能将其转换为谓词）。
      • 循环内调用函数（除非函数被内联）。
      • 指针别名：未使用 restrict 时数组可能重叠。

    大白话

    每轮循环只要依赖上一轮结果，或控制流和地址太复杂，编译器就不敢同时算多轮。它宁愿保守地生成正确标量代码，也不会冒险改变程序语义。

    • 检查自动向量化：使用编译器标志查看哪些内容被向量化：
    # GCC: show vectorisation decisions
g++ -O3 -march=native -fopt-info-vec-optimized code.cpp

# Clang: show vectorisation report
clang++ -O3 -march=native -Rpass=loop-vectorize code.cpp
    • 何时用内建函数，何时用自动向量化：从整洁 C++ 和编译器优化开始。若编译器向量化了循环，已经很好；若性能仍不够，查看编译器向量化报告理解原因，然后才为关键内层循环编写内建函数。过早使用内建函数会降低可读性，却无法保证收益。

    大白话

    不要一开始就把所有循环改成 NEON。先测量并看编译器报告，只有热点循环没有被正确向量化时，手写内建函数才值得付出维护成本。

    编程任务（在 ARM 上使用 g++ 或 clang++ 编译，Mac M 系列或 Linux aarch64）¶

    1. 编写标量点积和 NEON 向量化点积，对二者做基准测试并测量加速比。 

      // task1_neon_dot.cpp
// Compile (Mac/ARM Linux): clang++ -O3 -o task1 task1_neon_dot.cpp
// Note: NEON is enabled by default on AArch64, no special flags needed

#include <iostream>
#include <chrono>
#include <vector>
#include <arm_neon.h>

float dot_scalar(const float* a, const float* b, int n) {
    float sum = 0.0f;
    for (int i = 0; i < n; i++) {
        sum += a[i] * b[i];
    }
    return sum;
}

float dot_neon(const float* a, const float* b, int n) {
    float32x4_t sum_vec = vdupq_n_f32(0.0f);
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        float32x4_t va = vld1q_f32(a + i);
        float32x4_t vb = vld1q_f32(b + i);
        sum_vec = vfmaq_f32(sum_vec, va, vb);
    }
    float sum = vaddvq_f32(sum_vec);
    for (; i < n; i++) sum += a[i] * b[i];
    return sum;
}

int main() {
    const int N = 10'000'000;
    std::vector<float> a(N, 1.0f), b(N, 2.0f);

    // Warm up
    volatile float s1 = dot_scalar(a.data(), b.data(), N);
    volatile float s2 = dot_neon(a.data(), b.data(), N);

    // Benchmark scalar
    auto start = std::chrono::high_resolution_clock::now();
    for (int t = 0; t < 100; t++) {
        s1 = dot_scalar(a.data(), b.data(), N);
    }
    auto end = std::chrono::high_resolution_clock::now();
    double scalar_ms = std::chrono::duration<double, std::milli>(end - start).count() / 100;

    // Benchmark NEON
    start = std::chrono::high_resolution_clock::now();
    for (int t = 0; t < 100; t++) {
        s2 = dot_neon(a.data(), b.data(), N);
    }
    end = std::chrono::high_resolution_clock::now();
    double neon_ms = std::chrono::duration<double, std::milli>(end - start).count() / 100;

    std::cout << "Scalar: " << scalar_ms << " ms (result: " << s1 << ")\n";
    std::cout << "NEON:   " << neon_ms << " ms (result: " << s2 << ")\n";
    std::cout << "Speedup: " << scalar_ms / neon_ms << "x\n";
    return 0;
}

    2. 实现 NEON ReLU 与 softmax 最大值查找。使用不同操作练习加载→计算→存储模式。 

      // task2_neon_ops.cpp
// Compile: clang++ -O3 -o task2 task2_neon_ops.cpp

#include <iostream>
#include <vector>
#include <cmath>
#include <arm_neon.h>

void relu_neon(const float* in, float* out, int n) {
    float32x4_t zero = vdupq_n_f32(0.0f);
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        float32x4_t x = vld1q_f32(in + i);
        vst1q_f32(out + i, vmaxq_f32(x, zero));
    }
    for (; i < n; i++) out[i] = in[i] > 0 ? in[i] : 0;
}

float max_neon(const float* data, int n) {
    float32x4_t max_vec = vdupq_n_f32(-INFINITY);
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        max_vec = vmaxq_f32(max_vec, vld1q_f32(data + i));
    }
    float result = vmaxvq_f32(max_vec);
    for (; i < n; i++) result = result > data[i] ? result : data[i];
    return result;
}

int main() {
    std::vector<float> data = {-3, 1, -1, 4, 2, -5, 0, 7, -2, 3};
    std::vector<float> out(data.size());

    relu_neon(data.data(), out.data(), data.size());
    std::cout << "ReLU: ";
    for (float x : out) std::cout << x << " ";
    std::cout << "\n";

    float mx = max_neon(data.data(), data.size());
    std::cout << "Max: " << mx << " (expected: 7)\n";
    return 0;
}

    3. 比较自动向量化代码与手写 NEON 内建函数。使用 -fopt-info-vec（GCC）或 -Rpass=loop-vectorize（Clang）查看编译器行为。 

      // task3_auto_vs_manual.cpp
// Compile: clang++ -O3 -Rpass=loop-vectorize -o task3 task3_auto_vs_manual.cpp
//    (or): g++ -O3 -fopt-info-vec-optimized -o task3 task3_auto_vs_manual.cpp

#include <iostream>
#include <chrono>
#include <vector>
#include <arm_neon.h>

// Let the compiler auto-vectorise
void add_auto(const float* __restrict__ a, const float* __restrict__ b,
              float* __restrict__ c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}

// Hand-written NEON
void add_neon(const float* a, const float* b, float* c, int n) {
    int i = 0;
    for (; i + 4 <= n; i += 4) {
        vst1q_f32(c + i, vaddq_f32(vld1q_f32(a + i), vld1q_f32(b + i)));
    }
    for (; i < n; i++) c[i] = a[i] + b[i];
}

int main() {
    const int N = 10'000'000;
    std::vector<float> a(N, 1.0f), b(N, 2.0f), c(N);

    auto bench = [&](auto fn, const char* name) {
        fn(a.data(), b.data(), c.data(), N);  // warm up
        auto start = std::chrono::high_resolution_clock::now();
        for (int t = 0; t < 100; t++) fn(a.data(), b.data(), c.data(), N);
        auto end = std::chrono::high_resolution_clock::now();
        double ms = std::chrono::duration<double, std::milli>(end - start).count() / 100;
        std::cout << name << ": " << ms << " ms\n";
    };

    bench(add_auto, "Auto-vectorised");
    bench(add_neon, "Hand-written NEON");
    // They should be very close — the compiler auto-vectorises this simple loop well
    return 0;
}
