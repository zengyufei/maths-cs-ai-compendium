# 硬件基础

*在编写 SIMD 或 GPU 代码前，你必须理解自己正在编程的硬件。本节涵盖并行性为何取代时钟频率、现代 CPU 如何执行指令、SIMD 是什么、用于推理性能的 roofline 模型，以及芯片架构的全景。*

- 数十年来，软件能免费变快：购买一颗时钟频率更高的新 CPU，程序无需改一行就能变快。这个时代在约 2005 年结束。理解它为何结束及其替代物，对于想写出高性能代码的人至关重要。

!!! note "大白话"
    以前程序慢，换新 CPU 往往就能变快；现在这条路走不通了。想继续提速，程序本身必须能同时利用多个核心、向量单元或 GPU。

## 免费性能的终结

- **摩尔定律**（1965）观察到，芯片上的晶体管数量大约每两年翻倍。这一规律维持了 60 年。更多晶体管意味着更小的晶体管，进而意味着更高时钟频率和更快程序。

- 但约在 2005 年，时钟频率在约 4 GHz 撞上了墙。问题是**功耗**。芯片消耗的功率近似为：

$$P \propto C \cdot V^2 \cdot f$$

- 其中 $C$ 是电容（与晶体管数成比例），$V$ 是电压，$f$ 是时钟频率。要提高频率，必须提高电压以更快切换晶体管；但功耗随 $V^2 \cdot f$ 缩放，因此频率的小幅提高会导致功耗（和热量）大幅增加。4 GHz 时，芯片已达到 100 瓦以上；升到 8 GHz 需要不切实际的散热。

!!! note "大白话"
    芯片不是不能算更快，而是会先热得受不了。频率越高，耗电和发热增长得比直觉更快，散热很快成为硬上限。

- 解决方案是：不再让一个核心更快，而是在同一芯片上放置**多个核心**。3 GHz 的四核芯片与 4.5 GHz 单核芯片耗电相近，却可完成 4 倍并行工作。这正是现代 CPU 都有多核的原因，也是并行性（SIMD、多线程、GPU 计算）成为提升性能唯一道路的原因。

!!! note "大白话"
    与其强迫一个人跑到极限，不如让几个人同时干互不依赖的活。多核、SIMD 和 GPU 都是在用不同方式扩大“同时开工”的人数。

- **对机器学习的含义**：在一个核心上需要 10 分钟的训练步骤，无法仅靠购买更快 CPU 变快；只能通过更多核心（数据并行，第 6 章）、更宽 SIMD 单元（本章）或 GPU（数千个核心）来加速。

!!! note "大白话"
    机器学习中的大张量计算天然有大量相似工作可分开做。要压缩训练时间，关键是把这些工作拆给更多计算单元，而不是期待单核突然快十倍。

## 现代 CPU 如何执行指令

- 现代 CPU 核远比第 13 章的简单取指-译码-执行模型复杂。它采用多种技巧以每周期执行更多指令：

- **超标量执行**：CPU 有多个执行单元（ALU、FPU、加载/存储单元），可同时执行多条相互独立的指令。若不存在依赖，现代核心每周期可执行 4 至 6 条指令。

- **乱序执行（OoO）**：CPU 不按程序顺序执行指令，而是向前查看指令流，找出输入已就绪的指令并立即执行，无论其所在位置。这隐藏了延迟：当一条指令等待内存数据（100 个以上周期）时，CPU 执行其他已就绪指令。

- **分支预测**：条件分支（`if` 语句、循环条件）会带来不确定性，CPU 必须在条件求值后才知道路径。CPU 不会停顿，而是**预测**结果并沿预测路径推测执行。若预测正确（现代预测器准确率超过 95%），不损失时间；若预测错误，则丢弃推测工作、执行正确路径（约 15 个周期的代价）。

- **推测执行**：分支预测的扩展。CPU 执行*可能*不需要的指令，赌它们会需要，以填满流水线并让执行单元保持忙碌。

!!! note "大白话"
    CPU 会提前猜测下一步并先做一些准备，猜对就省等待，猜错再丢掉结果。这些技巧让单个核心很灵活，但它们不能替你把一个循环自动拆成大量数据并行工作。

- 这些都自动发生，无需程序员干预；但它们只帮助**指令级并行性（ILP）**，即单条流内的独立指令。对于**数据级并行性**，即对许多数据元素执行同一操作，需要 SIMD。

!!! note "大白话"
    ILP 是 CPU 在一串不同指令里见缝插针；SIMD 是让同一条指令同时处理多份数据。机器学习数组运算通常更依赖后者。

## SIMD：单指令，多数据

- **SIMD** 是用一条指令同时作用于多个数据元素的理念。不是将两个数字相加，而是用一条指令将两个含 4 个（或 8 个、16 个）数字的向量相加。

!!! note "大白话"
    SIMD 像把四个相同的小任务装进一个托盘一起加工。操作规则没有变，但一次执行处理了多份数据。

- 不使用 SIMD（标量）：

```cpp
// Add two arrays element by element: 4 add instructions
for (int i = 0; i < 4; i++) {
    c[i] = a[i] + b[i];  // one add per iteration
}
```

- 使用 SIMD（向量化）：

```cpp
// Add two arrays: 1 SIMD instruction does all 4 adds
#include <immintrin.h>  // x86 SIMD intrinsics

__m128 va = _mm_load_ps(a);    // load 4 floats into a 128-bit register
__m128 vb = _mm_load_ps(b);    // load 4 floats into another register
__m128 vc = _mm_add_ps(va, vb); // add all 4 pairs simultaneously
_mm_store_ps(c, vc);            // store 4 results
```

- SIMD 版本以原来四分之一的指令完成相同工作。通过每条指令处理 4 个而非 1 个浮点数，它可获得理论上 4 倍的加速。

!!! note "大白话"
    向量化并不是换了数学算法，而是把多次相同计算打包。理论倍数取决于一次能装多少数，实际速度还会被取数和存数拖住。

### 向量寄存器

- SIMD 指令操作**向量寄存器**，即容纳多个数据元素的宽寄存器。

| 寄存器宽度 | 浮点数（32 位） | 双精度数（64 位） | 名称 |
|----------------|-----------------|-------------------|------|
| 128 位 | 4 | 2 | SSE（x86）、NEON（ARM） |
| 256 位 | 8 | 4 | AVX/AVX2（x86） |
| 512 位 | 16 | 8 | AVX-512（x86） |
| 可变（128-2048） | 可变 | 可变 | SVE/SVE2（ARM） |

- 更宽的寄存器意味着更多并行性。一条 512 位 AVX-512 指令同时处理 16 个浮点数，相对标量代码理论上快 16 倍。实际加速更低，因为受内存带宽限制：计算速度可能快于向 CPU 供给数据的速度。

!!! note "大白话"
    寄存器越宽，一次能处理的数字越多，但数据必须先送到寄存器里。算得再快，内存送货跟不上，处理单元也只能等着。

- 对机器学习而言，float32 矩阵乘法从 SIMD 获益巨大。内层循环（两个向量的点积）直接映射为 SIMD 乘加指令。这就是 BLAS 库（NumPy 与 PyTorch 会调用）对 SIMD 做了如此深度优化的原因。

!!! note "大白话"
    矩阵乘法的核心就是不停做“对应元素相乘再相加”，非常适合批量装进 SIMD。成熟 BLAS 库已经把这种打包、缓存和并行细节优化得很深。

## Roofline 模型

- 如何知道代码是否够快？**roofline 模型**通过两项硬件上限刻画性能，为此提供框架：

1. **峰值计算能力**（FLOPS）：每秒最大浮点运算数。对于 4 GHz、256 位 AVX（每指令 8 个 float）和 2 个 FMA 单元的 CPU：$4 \times 10^9 \times 8 \times 2 = 64$ GFLOPS。

2. **峰值内存带宽**（字节/秒）：从内存向 CPU 移动数据的速度。现代 CPU 的内存带宽可能为 50 GB/s。

- 代码的**算术强度**是计算量与内存访问量之比：

$$\text{Arithmetic Intensity} = \frac{\text{FLOPS}}{\text{Bytes transferred}}$$

!!! note "大白话"
    算术强度问的是：每搬运 1 字节数据，究竟做了多少计算。这个比例决定程序是在等内存，还是在等计算单元完成运算。

- 若算术强度低（每加载一个字节只做少量操作），代码就是**内存受限**：大部分时间在等待数据。提升计算速度（更宽 SIMD、更高频率）无济于事。

!!! note "大白话"
    内存受限时，工人没有原料可加工。继续增加计算能力没有用，应该少搬数据、复用缓存数据，或让内存传输更有效率。

- 若算术强度高（每字节进行大量操作），代码就是**计算受限**：大部分时间在计算。更快内存无济于事。

!!! note "大白话"
    计算受限时，数据已经够快地送到了，真正排队的是运算本身。这时更宽 SIMD、更多核心、更强 GPU 才会直接带来收益。

- roofline：

$$\text{Achievable FLOPS} = \min\left(\text{Peak FLOPS}, \; \text{Bandwidth} \times \text{Arithmetic Intensity}\right)$$

!!! note "大白话"
    实际性能永远取两道天花板中更低的一道：要么算力不够，要么带宽不够。优化前先判断撞上哪块天花板，才能避免用错力。

- **矩阵乘法**具有高算术强度：在 $O(n^2)$ 数据上进行 $O(n^3)$ 操作，因而强度 $\approx O(n)$。大矩阵时它受计算限制。这就是 GPU（计算能力高）主导以矩阵为主的机器学习工作负载的原因。

!!! note "大白话"
    矩阵里的每个数据会被反复使用，所以搬一次能算很多次。GPU 最擅长这种把大量计算堆在同一批数据上的任务。

- **逐元素操作**（ReLU、加法、乘法）具有低算术强度：每个加载元素仅 1 次操作。它们受内存限制。让 GPU 更快并不会有帮助，需要更快内存，或将这些操作与计算密集型操作融合，避免独立的内存往返。

!!! note "大白话"
    ReLU 这类操作每个数只做一下判断，却仍要读进来再写出去，搬运比计算更贵。单独优化算术指令收益很小，少一次读写通常更重要。

- roofline 模型解释了**内核融合**为何如此重要：将 matmul、bias add 和 ReLU 合并到一个内核，可避免中间结果写回内存再读出，将三个内存受限操作变为一个计算受限操作。

!!! note "大白话"
    融合相当于在同一张工作台连续完成几道工序，不把半成品反复搬去仓库又取回来。减少中间张量的读写，经常比单独把某一步算快更有效。

## 延迟与吞吐量

- **延迟**是完成一次操作的时间，**吞吐量**是单位时间完成的操作数。

!!! note "大白话"
    延迟看一件事要等多久，吞吐量看一段时间总共能做多少件事。两者常常不能同时做到最好。

- 类比：公交车延迟高（每一站都停），但吞吐量高（一次载 50 人）；出租车延迟低（直达目的地），但吞吐量低（载 1 至 4 人）。

- GPU 是公交车：单次操作延迟高（每条指令完成需许多周期），但吞吐量巨大（数千核心同时处理）。CPU 是出租车：延迟低（乱序执行、分支预测和深层缓存最小化等待），但吞吐量有限（4 至 64 核）。

- 因此 GPU 更适合机器学习训练（吞吐量重要，要处理数百万样本），而 CPU 更适合操作系统任务（延迟重要，需要立即响应按键）。

!!! note "大白话"
    GPU 需要先把大批工作攒起来才划算，但一旦开工总产量极高；CPU 擅长快速处理零散且分支复杂的请求。选硬件先看工作是“很多同类任务”还是“少量紧急任务”。

- **流水线化**将延迟转化为吞吐量。若一条指令需要 5 个周期、但流水线每周期启动一条新指令，则吞吐量为每周期 1 条指令（即使每条指令完成需 5 周期）。这与第 13 章 CPU 流水线原则相同，但适用于每一层：SIMD 单元、内存控制器和 GPU 核都采用流水线。

!!! note "大白话"
    流水线像装配线：第一件产品还没做完，后面的工位已经能开始下一件。单件完成时间没变，但连续处理时每个周期都能产出结果。

## 芯片架构全景

- 要编写代码的硬件决定可用的 SIMD 指令：

### x86（Intel、AMD）

- 主导台式机、笔记本和数据中心 CPU。SIMD：SSE（128 位）、AVX/AVX2（256 位）、AVX-512（512 位）。Intel AMX 为 AI 工作负载提供专用矩阵乘法单元。

- **优势**：最高单核性能、最宽 SIMD、成熟的软件生态（MKL、oneDNN）。
- **劣势**：高功耗、复杂指令集、昂贵。

!!! note "大白话"
    x86 通常性能和软件支持都强，代价是功耗、成本和复杂度也较高。它适合高性能桌面和服务器，但不一定适合电池供电的小设备。

### ARM

- 主导移动端（每部智能手机），并在服务器（AWS Graviton、Ampere Altra）和笔记本（Apple M 系列）增长。SIMD：NEON（128 位）、SVE/SVE2（可伸缩，128 至 2048 位）。

- **优势**：优异的能效（每瓦性能）、可定制核心（Apple M4 以一小部分功耗实现可与 Intel 匹敌的单核性能）。
- **劣势**：SIMD 较窄（NEON 仅 128 位，尽管 SVE 可更宽）、HPC 软件生态较小。

!!! note "大白话"
    ARM 把每瓦性能放在前面，因此很适合手机和越来越多的服务器。不同 ARM 芯片能力差异较大，做底层优化时不能默认它们都和 x86 一样。

### Apple Silicon（M1/M2/M3/M4）

- 基于 ARM 并有自定义扩展。包括 **AMX**（Apple Matrix eXtensions），即 Accelerate 框架用于 BLAS 操作的未公开矩阵乘法单元。统一内存架构让 CPU 和 GPU 共享同一物理内存，消除 CPU↔GPU 复制瓶颈。

- **对机器学习而言**：Apple Neural Engine（16 核专用机器学习加速器）与统一内存，使 M 系列芯片出人意料地适合本地机器学习推理和小规模训练。但没有 CUDA，必须使用 Metal（Apple 的 GPU API）或 MLX（Apple 的机器学习框架）。

!!! note "大白话"
    Apple Silicon 的 CPU、GPU 共用一份内存，少了来回复制数据的开销，适合本地模型实验。但 CUDA 是 NVIDIA 专用生态，在 Mac 上需要换成 Metal 或 MLX。

### RISC-V

- 开源 ISA，没有许可费用（不同于 ARM）。正在嵌入式系统、IoT 和研究中增长。SIMD：“V”（vector）扩展提供与 ARM SVE 相似的可伸缩向量处理。

- **对机器学习而言**：尚无法在机器学习工作负载上与 x86/ARM 竞争，但值得关注。多家 AI 加速器初创公司使用 RISC-V 核心。

!!! note "大白话"
    RISC-V 的价值主要是开放和可定制，而不是现在就跑大模型最快。它更常作为嵌入式设备或专用加速器里的可控核心。

### GPU（NVIDIA、AMD、Intel）

- 第 04 至 05 节会深入介绍。数千个针对吞吐量优化的简单核心。NVIDIA 以 CUDA 主导机器学习，AMD 以 ROCm 竞争，Intel 以 Arc GPU 和 Gaudi 加速器进入市场。

!!! note "大白话"
    GPU 的强项是让成千上万个较简单的核心做相同类型的工作。软件生态同样决定能否用好硬件，目前 CUDA 的成熟度是 NVIDIA 在机器学习中占优的重要原因。

### TPU（Google）

- 专为机器学习设计的定制 ASIC，使用针对矩阵乘法优化的脉动阵列。第 05 节将介绍。

!!! note "大白话"
    TPU 是把机器学习最常见的矩阵乘法直接做成专用硬件。它不像通用 CPU 那样什么都能高效做，而是用专用性换取特定任务的效率。

## 热设计与功耗约束

- 性能最终受功耗和散热限制：

- **TDP（热设计功耗）**：芯片可持续消耗的最大功率。笔记本 CPU 可能为 15W TDP，服务器 CPU 为 250W，数据中心 GPU 为 700W（NVIDIA B200）。

- **暗硅（dark silicon）**：任一时刻，大部分晶体管必须关断，才能保持在热预算内。芯片理论上可以同时使用全部晶体管，但会熔毁。

!!! note "大白话"
    芯片上并不是所有电路都能同时全速运行，因为电和热的预算不允许。硬件资源存在，不等于可以在同一时刻全部开满。

- **能效**（FLOPS/瓦）日益成为比原始 FLOPS 更重要的指标，原因包括：
    - ARM 正在接管数据中心（每瓦 FLOPS 优于 x86）。
    - TPU 尽管峰值 FLOPS 较低，仍可与 GPU 竞争（机器学习工作负载每瓦 FLOPS 好得多）。
    - 量化（INT8、FP8）不仅节省内存，也降低每次运算的功耗。

- 大规模机器学习中，训练前沿 LLM 会连续数月消耗数兆瓦电力；电费可能超过硬件成本。能效直接影响 AI 研究的经济性。

!!! note "大白话"
    大模型训练不只是算法问题，也是电力账单问题。每次少做无用计算、用更低精度或更高能效硬件，规模放大后都会变成真实成本差异。

## 实践：在 C++ 中测量性能

- 要推理性能，必须测量性能。下面是最小 C++ 基准测试设置：

```cpp
#include <iostream>
#include <chrono>
#include <vector>

// Scalar addition
void add_scalar(const float* a, const float* b, float* c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];
    }
}

int main() {
    const int N = 1 << 24;  // ~16 million elements
    std::vector<float> a(N, 1.0f), b(N, 2.0f), c(N);

    // Warm up (fill caches, trigger frequency scaling)
    add_scalar(a.data(), b.data(), c.data(), N);

    // Benchmark
    auto start = std::chrono::high_resolution_clock::now();

    for (int trial = 0; trial < 100; trial++) {
        add_scalar(a.data(), b.data(), c.data(), N);
    }

    auto end = std::chrono::high_resolution_clock::now();
    double elapsed = std::chrono::duration<double>(end - start).count();

    double total_bytes = 3.0 * N * sizeof(float) * 100;  // read a, read b, write c
    double bandwidth = total_bytes / elapsed / 1e9;        // GB/s

    std::cout << "Time: " << elapsed << " s\n";
    std::cout << "Bandwidth: " << bandwidth << " GB/s\n";

    return 0;
}
```

```bash
# Compile with optimisations
g++ -O3 -march=native -o bench bench.cpp
./bench
```

!!! note "大白话"
    性能优化先测再说。这个基准会重复执行同一操作，并按读写的数据量计算带宽，避免只凭感觉判断哪种实现更快。

- **本代码中的关键 C++ 概念**：
    - `#include <vector>`：动态数组（`std::vector<float>`），类似 Python 的 `list`，但具有类型且内存连续。
    - `a.data()`：返回指向底层数组的原始指针（`float*`），SIMD 内建函数需要它。
    - `std::chrono`：基准测试的高精度计时器。
    - `-O3`：最高编译器优化级别。编译器可能自动向量化循环（自动使用 SIMD）；`-march=native` 启用 CPU 支持的所有 SIMD 指令。

- **为何预热**：首次运行会填充缓存，也可能触发 CPU 频率缩放（turbo boost）；后续运行更有代表性。

!!! note "大白话"
    第一次运行常常包含缓存未命中和升频等一次性成本，不能代表稳定速度。预热后再测，结果才更接近日常持续运行的表现。

- **为何测量带宽**：对内存受限操作（如逐元素加法），有意义的指标是带宽（GB/s），而不是 FLOPS。若实测带宽接近硬件上限（DDR5 约 50 GB/s），就受内存限制，SIMD 帮助不大，瓶颈是内存而不是计算。

!!! note "大白话"
    逐元素加法的重点不是每秒做了多少次加法，而是每秒搬了多少数据。带宽已经接近硬件上限时，再改算术代码通常不会带来明显提升。

```python
import jax.numpy as jnp

def arithmetic_intensity(flops, bytes_transferred):
    return flops / bytes_transferred

# Element-wise ReLU: 1 comparison per element, read + write
n = 1024
relu_flops = n  # 1 op per element
relu_bytes = 2 * n * 4  # read input + write output (float32)
print(f"ReLU: {arithmetic_intensity(relu_flops, relu_bytes):.2f} FLOPS/byte → memory-bound")

# Matrix multiply: 2*n^3 ops, read 2*n^2 + write n^2 floats
matmul_flops = 2 * n**3
matmul_bytes = 3 * n**2 * 4  # read A + read B + write C
print(f"Matmul ({n}×{n}): {arithmetic_intensity(matmul_flops, matmul_bytes):.0f} FLOPS/byte → compute-bound")

# Layer norm: ~5n ops (mean, var, normalise), read + write
ln_flops = 5 * n
ln_bytes = 2 * n * 4
print(f"LayerNorm: {arithmetic_intensity(ln_flops, ln_bytes):.2f} FLOPS/byte → memory-bound")

# Convolution 3x3: 2*9*C_in*C_out*H*W, read kernel + feature map + write output
C_in, C_out, H, W = 64, 128, 32, 32
conv_flops = 2 * 9 * C_in * C_out * H * W
conv_bytes = (9 * C_in * C_out + C_in * H * W + C_out * H * W) * 4
print(f"Conv3x3: {arithmetic_intensity(conv_flops, conv_bytes):.0f} FLOPS/byte → compute-bound")
```

2. 说明并行性为何重要。随着数据规模增长，比较顺序执行与并行（NumPy）执行。
```python
import numpy as np
import time

for n in [1000, 10000, 100000, 1000000, 10000000]:
    a = np.random.randn(n).astype(np.float32)
    b = np.random.randn(n).astype(np.float32)

    # "Sequential" (Python loop)
    start = time.time()
    c = [a[i] * b[i] for i in range(min(n, 100000))]  # cap at 100K for sanity
    seq_time = time.time() - start
    if n > 100000:
        seq_time *= n / 100000  # extrapolate

    # "Parallel" (NumPy, uses SIMD + multithreading internally)
    start = time.time()
    c = a * b
    par_time = time.time() - start

    print(f"n={n:>10,}  sequential={seq_time:.4f}s  parallel={par_time:.6f}s  "
          f"speedup={seq_time/par_time:.0f}x")
```
