# Triton 与 TPU

*CUDA C 功能强大但冗长。Triton 让你能用 Python 编写 GPU 内核。TPU 以不同取舍提供 GPU 之外的选择。本节涵盖 Triton 内核编程、作为案例的 Flash Attention、TPU 架构与 JAX/Pallas，以及如何选择正确工具。Vulkan 和跨平台 GPU 计算见第 07 节。*

- 前一节讲解了 CUDA C GPU 编程。本节沿抽象阶梯向上：Triton 用 Python 以 20% 的工作量获得 CUDA 约 80% 的性能。TPU 和 Vulkan 则为特定用例提供替代硬件目标。

## Triton：用 Python 编写 GPU 内核

- **Triton**（OpenAI）是用于编写 GPU 内核的 Python 语言。你不必像 CUDA 那样推理单个线程，而是推理数据的**块（block）**。Triton 编译器会自动处理线程映射、内存合并、共享内存管理和多项优化。

- **Triton 为何重要**：CUDA C 要求深入了解 warp 调度、共享内存 bank conflict、寄存器压力与合并模式。Triton 抽象掉大部分细节，让懂 Python 而不懂系统编程的机器学习研究者也能开发 GPU 内核。

### 第一个 Triton 内核

```python
import triton
import triton.language as tl
import torch

@triton.jit
def add_kernel(
    x_ptr, y_ptr, output_ptr,
    n_elements,
    BLOCK_SIZE: tl.constexpr,  # compile-time constant
):
    # Each program instance processes one block of BLOCK_SIZE elements
    pid = tl.program_id(axis=0)  # which block am I?
    block_start = pid * BLOCK_SIZE

    # Offsets for this block
    offsets = block_start + tl.arange(0, BLOCK_SIZE)

    # Mask to handle the case where n_elements is not a multiple of BLOCK_SIZE
    mask = offsets < n_elements

    # Load data (masked: out-of-bounds reads return 0)
    x = tl.load(x_ptr + offsets, mask=mask)
    y = tl.load(y_ptr + offsets, mask=mask)

    # Compute
    output = x + y

    # Store result
    tl.store(output_ptr + offsets, output, mask=mask)


def add(x: torch.Tensor, y: torch.Tensor) -> torch.Tensor:
    output = torch.empty_like(x)
    n_elements = output.numel()

    # Launch: one program per block
    grid = lambda meta: (triton.cdiv(n_elements, meta['BLOCK_SIZE']),)
    add_kernel[grid](x, y, output, n_elements, BLOCK_SIZE=1024)

    return output


# Usage
x = torch.randn(1000000, device='cuda')
y = torch.randn(1000000, device='cuda')
z = add(x, y)
```

- **与 CUDA 的关键差异**：
    - 无显式线程管理，思考单位是**块**（程序实例），不是线程。
    - `tl.arange(0, BLOCK_SIZE)` 为整个块创建偏移量向量，对其的所有操作都隐式向量化。
    - `mask` 处理边界条件，与第 03 节 AVX-512 掩码寄存器相似，无需标量清理循环。
    - `tl.load` 与 `tl.store` 自动处理合并访问。
    - `@triton.jit` 在首次调用时将函数编译为 PTX（GPU 汇编），再缓存编译内核。

### Triton Softmax 内核

- Softmax 是 Triton 的好例子：它需多次遍历数据（max、减法、exp、sum、除法），且从在多次遍历间将数据留在 SRAM（共享内存）中获益：

```python
@triton.jit
def softmax_kernel(
    output_ptr, input_ptr, input_row_stride, output_row_stride, n_cols,
    BLOCK_SIZE: tl.constexpr,
):
    # Each program handles one row
    row_idx = tl.program_id(0)
    row_start = input_ptr + row_idx * input_row_stride

    # Load the row
    col_offsets = tl.arange(0, BLOCK_SIZE)
    mask = col_offsets < n_cols
    row = tl.load(row_start + col_offsets, mask=mask, other=-float('inf'))

    # Softmax: max for numerical stability, then exp, then normalise
    row_max = tl.max(row, axis=0)
    numerator = tl.exp(row - row_max)
    denominator = tl.sum(numerator, axis=0)
    softmax_output = numerator / denominator

    # Store result
    output_start = output_ptr + row_idx * output_row_stride
    tl.store(output_start + col_offsets, softmax_output, mask=mask)
```

- 在 PyTorch 中，`F.softmax(x, dim=-1)` 会启动 3 个独立内核（max、exp-and-sum、divide），每一个都读写全局内存。Triton 版本在单一内核中完成所有工作，将数据留在寄存器/SRAM 中。这种**内核融合**使自定义 Triton 内核可比 PyTorch 内置操作快 2 至 4 倍。

### Triton 自动调优

- Triton 支持**自动调优**：尝试多个配置并选择最快者：

```python
@triton.autotune(
    configs=[
        triton.Config({'BLOCK_SIZE_M': 128, 'BLOCK_SIZE_N': 128, 'BLOCK_SIZE_K': 32}),
        triton.Config({'BLOCK_SIZE_M': 64, 'BLOCK_SIZE_N': 256, 'BLOCK_SIZE_K': 32}),
        triton.Config({'BLOCK_SIZE_M': 256, 'BLOCK_SIZE_N': 64, 'BLOCK_SIZE_K': 64}),
    ],
    key=['M', 'N', 'K'],  # re-tune when these change
)
@triton.jit
def matmul_kernel(a_ptr, b_ptr, c_ptr, M, N, K, ...):
    ...
```

- Triton 在实际硬件上对每种配置做基准测试并选择最快版本。最优 tile 大小取决于 GPU 架构、矩阵维度和内存布局，自动调优无需人工试验即可找到它。

### Triton 与 CUDA：何时使用

| | Triton | CUDA C |
|--|--------|--------|
| 语言 | Python | C/C++ |
| 抽象 | 块级 | 线程级 |
| 开发速度 | 快（每内核 10-50 行） | 慢（100-500 行） |
| 性能上限 | 手调 CUDA 的约 80-95% | 100%（完整硬件控制） |
| 共享内存 | 自动 | 手动 |
| 合并访问 | 自动 | 手动 |
| Warp 级原语 | 有限 | 完整（shuffle、vote 等） |
| 硬件支持 | 仅 NVIDIA（AMD 实验性） | 仅 NVIDIA |

- **使用 Triton**：融合内核、自定义注意力模式、激活函数、大多数机器学习研究内核需求。
- **使用 CUDA C**：追求极致性能（最后 5 至 20%）、warp 级原语、复杂数据依赖并行，以及 Triton 无法表达的模式。

## 案例研究：Flash Attention

- **Flash Attention**（Dao 等，2022）是近期机器学习中影响最大的自定义内核。它用 $O(n)$ 内存而非 $O(n^2)$ 计算注意力，从而支持更长序列。

- **问题**：标准注意力计算 $\text{softmax}(QK^T / \sqrt{d}) \cdot V$。$QK^T$ 是 $n \times n$ 矩阵，$n$ 为序列长度。对于 $n = 128K$，矩阵大小为 $128K \times 128K \times 4$ 字节 = 64 GB，无法放入 GPU 内存。

- **洞见**：无需物化完整 $n \times n$ 矩阵，可以按**tile**计算注意力：加载一个 $Q$ 块、一个 $K$ 块，计算部分注意力分数、累加，再移动到下一块。整个 $n \times n$ 矩阵永不完整物化，SRAM 中一次只存在一个 tile。

- **在线 softmax**：难点在于 softmax 为数值稳定性需要知道整行最大值。Flash Attention 使用**在线 softmax**技巧：维持运行中的最大值，在发现新最大值时重新缩放先前计算的值。这使 softmax 可逐 tile 增量计算。

- 算法：

```
For each block of Q rows:
    For each block of K columns:
        1. Load Q_block from HBM to SRAM
        2. Load K_block from HBM to SRAM
        3. Compute S_block = Q_block @ K_block.T (in SRAM)
        4. Update running max, rescale previous results
        5. Compute exp(S_block - running_max)
        6. Update running sum and output accumulator
    Load V_block and compute final output
    Write output block back to HBM
```

- **为何快**：内层循环完全在 SRAM（共享内存）中运行。全局内存（HBM）只用于加载 Q、K、V 块并写入最终输出。数据复用系数与 SRAM 容量成比例，SRAM 访问比 HBM 快约 100 倍。

- Flash Attention 同时以 Triton 和 CUDA C 实现。CUDA 版本更快，效率约高 10%；但 Triton 版本更易读和修改，这对研究新注意力变体很重要。

## TPU 架构

- **TPU**（Tensor Processing Unit）是 Google 的定制机器学习加速器，采用与 GPU 截然不同的方法：

- **脉动阵列**：TPU 的核心计算单元是**矩阵乘法单元（MXU）**，即 128×128 或 256×256 脉动阵列。它让数据流过由乘加单元组成的网格来计算矩阵乘法：数据从边缘进入、在阵列传播，每个单元进行一次乘加并将结果传给下一个单元。

- GPU 调度数千条独立线程，脉动阵列则是单一、确定的数据流：没有线程调度、warp 分歧或分支预测。这种简单性使 MXU 在矩阵乘法上极具能效。

- **HBM**：TPU 使用与 GPU 相同的高带宽内存。TPU v5e 每芯片有 16 GB HBM2e，TPU v5p 有 95 GB HBM2e。

- **ICI**（Inter-Chip Interconnect）：TPU pod 使用定制高速网络连接数百个 TPU。JAX 原生支持跨 TPU pod 的数据并行与模型并行（第 6 章）。

- **BFloat16**：TPU 最早使用 bfloat16（第 13 章第 02 节）。BF16 具有与 float32 相同的指数范围，可防止训练溢出，尾数精度却较低。这种取舍非常适合机器学习：梯度值跨度大，但不需要 23 位精度。

### 编程 TPU：JAX 与 Pallas

- TPU 通过 **JAX** 和 **XLA** 编程。你写 Python/JAX，`jax.jit` 编译为 XLA HLO，XLA 再将 HLO 编译为 TPU 专用指令。不需要 CUDA 或 C++。

```python
import jax
import jax.numpy as jnp

@jax.jit
def matmul(a, b):
    return jnp.dot(a, b)

# This runs on CPU, GPU, or TPU depending on the device
a = jnp.ones((1024, 1024))
b = jnp.ones((1024, 1024))
c = matmul(a, b)
```

- **Pallas** 是 JAX 的内核创作 API，相当于 JAX 版 Triton。它让你编写由 XLA 为 GPU 或 TPU 编译的低层内核：

```python
from jax.experimental import pallas as pl
import jax.numpy as jnp

def add_kernel(x_ref, y_ref, o_ref):
    o_ref[...] = x_ref[...] + y_ref[...]

def add_pallas(x, y):
    return pl.pallas_call(
        add_kernel,
        out_shape=jax.ShapeDtypeStruct(x.shape, x.dtype),
        grid=(x.shape[0] // 128,),
        in_specs=[pl.BlockSpec((128,), lambda i: (i,)),
                  pl.BlockSpec((128,), lambda i: (i,))],
        out_specs=pl.BlockSpec((128,), lambda i: (i,)),
    )(x, y)
```

- Pallas 比 Triton 更新也更不成熟，但它是为 TPU 编写自定义内核的唯一方式，因为 TPU 不支持 CUDA。

### GPU 与 TPU

| | GPU（NVIDIA） | TPU（Google） |
|--|-------------|--------------|
| 可用性 | 任意云、私有部署 | 仅 Google Cloud |
| 编程 | CUDA C、Triton、PyTorch | JAX/XLA、Pallas |
| 灵活性 | 通用计算 | 为矩阵密集型机器学习优化 |
| 峰值 matmul FLOPS | 很高（Tensor Core） | 很高（MXU） |
| 非 matmul 操作 | 好 | 较慢（经向量单元而非 MXU） |
| 多芯片扩展 | NVLink（8 GPU）、InfiniBand | ICI（数千 TPU，集成更紧密） |
| 成本效率 | 有竞争力 | 大规模训练通常更便宜 |
| 生态 | 最大（PyTorch、TensorFlow、JAX） | 以 JAX 为中心 |

- **使用 GPU**：大多数机器学习工作负载、基于 PyTorch 的研究、推理服务、存在显著非 matmul 计算的工作负载。
- **使用 TPU**：大规模 JAX 训练（数千芯片）、Google Cloud 上注重成本的训练、由矩阵乘法主导的工作负载。

## 选择正确工具

| 工作负载 | 最佳工具 | 原因 |
|----------|-----------|-----|
| 机器学习训练（PyTorch） | NVIDIA GPU + CUDA/Triton | 最大生态、最佳工具链 |
| 机器学习训练（JAX、大规模） | TPU 或 NVIDIA GPU | Google 规模时 TPU 成本好，GPU 灵活性好 |
| 自定义融合内核 | Triton（Python）或 CUDA C | Triton 开发快，CUDA 达峰值性能 |
| JAX 自定义内核 | Pallas | TPU 唯一选择，也能用于 GPU |
| 跨平台推理 | Vulkan（第 07 节）或 ONNX Runtime | 可在任意 GPU 厂商上运行 |
| 移动/边缘推理 | Metal（Apple）、Vulkan（Android）、NNAPI | 平台专用加速器 |
| 浏览器推理 | WebGPU（第 07 节） | 浏览器中唯一选择 |
| 仅 CPU 推理 | ONNX Runtime + AVX/NEON | 无需 GPU，使用 SIMD（第 02-03 节） |
| 新颖硬件 | 厂商专用 SDK | 每个加速器有自己的工具链 |

## 编程任务（使用带 GPU 运行时的 CoLab）

1. 编写并运行向量加法 Triton 内核，与 PyTorch 内置加法比较性能。
```python
import triton
import triton.language as tl
import torch
import time

@triton.jit
def add_kernel(x_ptr, y_ptr, out_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < n
    x = tl.load(x_ptr + offs, mask=mask)
    y = tl.load(y_ptr + offs, mask=mask)
    tl.store(out_ptr + offs, x + y, mask=mask)

n = 10_000_000
x = torch.randn(n, device='cuda')
y = torch.randn(n, device='cuda')

# Triton
out_triton = torch.empty_like(x)
grid = lambda meta: (triton.cdiv(n, meta['BLOCK']),)
add_kernel[grid](x, y, out_triton, n, BLOCK=1024)

# PyTorch
out_torch = x + y

# Verify correctness
assert torch.allclose(out_triton, out_torch, atol=1e-5)

# Benchmark
torch.cuda.synchronize()
start = time.time()
for _ in range(1000):
    add_kernel[grid](x, y, out_triton, n, BLOCK=1024)
torch.cuda.synchronize()
triton_time = (time.time() - start) / 1000

start = time.time()
for _ in range(1000):
    out_torch = x + y
torch.cuda.synchronize()
torch_time = (time.time() - start) / 1000

print(f"Triton:  {triton_time*1000:.3f} ms")
print(f"PyTorch: {torch_time*1000:.3f} ms")
print(f"Ratio:   {torch_time/triton_time:.2f}x")
```

2. 编写单次完成乘法 + 加法 + ReLU 的 Triton 融合内核，与三个独立 PyTorch 操作比较。
```python
import triton
import triton.language as tl
import torch
import time

@triton.jit
def fused_mul_add_relu_kernel(x_ptr, w_ptr, b_ptr, out_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < n
    x = tl.load(x_ptr + offs, mask=mask)
    w = tl.load(w_ptr + offs, mask=mask)
    b = tl.load(b_ptr + offs, mask=mask)
    result = tl.maximum(x * w + b, 0.0)  # fused: mul + add + relu
    tl.store(out_ptr + offs, result, mask=mask)

n = 10_000_000
x = torch.randn(n, device='cuda')
w = torch.randn(n, device='cuda')
b = torch.randn(n, device='cuda')

# Fused (Triton)
out_fused = torch.empty_like(x)
grid = lambda meta: (triton.cdiv(n, meta['BLOCK']),)
fused_mul_add_relu_kernel[grid](x, w, b, out_fused, n, BLOCK=1024)

# Unfused (PyTorch)
out_unfused = torch.relu(x * w + b)

assert torch.allclose(out_fused, out_unfused, atol=1e-5)

# Benchmark
torch.cuda.synchronize()
start = time.time()
for _ in range(1000):
    fused_mul_add_relu_kernel[grid](x, w, b, out_fused, n, BLOCK=1024)
torch.cuda.synchronize()
fused_time = (time.time() - start) / 1000

start = time.time()
for _ in range(1000):
    out_unfused = torch.relu(x * w + b)
torch.cuda.synchronize()
unfused_time = (time.time() - start) / 1000

print(f"Fused (Triton):    {fused_time*1000:.3f} ms")
print(f"Unfused (PyTorch): {unfused_time*1000:.3f} ms")
print(f"Speedup:           {unfused_time/fused_time:.2f}x")
```

3. 测量 JAX 的 XLA 编译器如何自动融合操作，比较使用与不使用 jit 的操作链。
```python
import jax
import jax.numpy as jnp
import time

def chain_ops(x):
    x = x * 2.0
    x = x + 1.0
    x = jnp.maximum(x, 0.0)  # ReLU
    x = x / jnp.sum(x)
    return x

chain_jit = jax.jit(chain_ops)
x = jax.random.normal(jax.random.PRNGKey(0), (10000, 1000))

# Warm up
_ = chain_jit(x)
jax.block_until_ready(_)

# Eager (each op is a separate kernel launch)
start = time.time()
for _ in range(100):
    y = chain_ops(x)
jax.block_until_ready(y)
eager_time = (time.time() - start) / 100

# JIT (XLA fuses operations)
start = time.time()
for _ in range(100):
    y = chain_jit(x)
jax.block_until_ready(y)
jit_time = (time.time() - start) / 100

print(f"Eager: {eager_time*1000:.2f} ms")
print(f"JIT:   {jit_time*1000:.2f} ms")
print(f"Speedup: {eager_time/jit_time:.1f}x (XLA fuses the 4 operations into 1 kernel)")
```
